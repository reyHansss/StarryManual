## 一个界面，两份数据

Starry 的玩家设置界面统一用 GameSettings 搭建。输入层不再维护单独的设置 ViewModel、修改跟踪和第二套保存流程。界面统一，数据仍按职责分开存放：

| 数据                               | 存在哪里                                                        |
| ---------------------------------- | --------------------------------------------------------------- |
| 灵敏度、反转、死区、瞄准倍率等偏好 | `UStarrySettingsShared`（玩家的共享设置）                       |
| 按键映射与 Profile                 | `UStarryInputUserSettings`，基于 Enhanced Input 的 UserSettings |

## 让一个功能的按键出现在设置页

**前提**：设置层根据已登记到 UserSettings 的 IMC 生成改键条目，不会自动扫描项目里所有资产。所以：

1. 在 IMC 中把映射配置为玩家可修改的；
2. 在构建设置树之前，把相关 IMC 登记到 UserSettings。

**IMC 怎样被登记**

- Manager 添加一份 Setup 时，默认会把它的 IMC 登记到 UserSettings（`bNotifyUserSettings = true`）。
- Manager 移除 Setup 时不会通知 UserSettings，所以**应用过一次的 IMC 会一直留在 UserSettings 里**，之后的设置页仍会显示它。
- 想让还没有进入的功能也提前出现在设置页，需要显式预先登记它的 IMC。

**改键入口**

- 键鼠的改键条目由 `UStarrySettingKeyboardInput` 访问原生 UserSettings。改键沿用 GameSettings 的编辑、应用、保存流程，不要直接修改 IMC 资产来当作玩家的个人配置。
- 代码中可以调用 Manager 的 `RemapKey` 与 `SaveInputSettings`。`UStarryInputUserSettings` 在保存开始、完成和失败时分别广播 `OnSaveSettingsStarted`、`OnSaveSettingsCompleted`、`OnSaveSettingsFailed`。

## 应用与保存

玩家点击应用时，设置 Registry 的 `SaveChanges` 依次执行：

1. 基类保存；
2. `LocalSettings->ApplySettings(false)`：应用分辨率等本机设置，这一步会间接保存配置；
3. `SharedSettings->ApplySettings()`：应用字幕、后台音频、语言等偏好，并处理输入相关的设置；
4. `SharedSettings->SaveSettings()`：保存共享设置。

灵敏度没有在应用时被“写进”输入系统，而是由输入修饰器在运行时读取当前偏好；对应的 `ApplyInputSensitivity` 目前是空函数。

调试时分清三种状态：

- 界面上已经改了；
- 已经应用了；
- 已经持久保存了。

只有重启后结果还在，才说明持久数据被正确读取。不要在 Handler 里另存一份灵敏度，也不要另写一个界面重新实现保存，否则设置页、实际输入与存档会互相脱节。

## 当前覆盖范围

**已经有的**：键鼠的改键入口。

**还没有完整接入的**：

- 手柄的改键条目；
- 跨 Profile、跨硬件写入；
- Tooltip 与 InputFilter 的桥接。

底层已有的类型不代表这些界面已经完成。

**排查**

| 现象                     | 依次检查                                                       |
| ------------------------ | -------------------------------------------------------------- |
| 某个功能没有出现在设置页 | 映射是否可由玩家修改；IMC 是否在建树之前登记；设置条目是否创建 |
| 当前能用，但重启后不保留 | 沿着上面的应用与保存流程逐步追踪                               |

修饰器的职责见[修饰器与触发器](/read/input-triggers)，配置实际应用时的选项见[配置与生命周期](/read/input-binding#添加映射时的选项)。

代码位置：`Framework/Settings/StarrySettingsShared`、`Framework/Settings/StarryGameSettingRegistry`、`Framework/Settings/CustomSettings/StarrySettingKeyboardInput`、`Framework/Input/StarryInputUserSettings`。
