## 两个动作入口，一个观察工具

玩家从设备输入到达 Input Handler，AI 从当前机会选择 Behavior／Logic。两条路径最终使用项目已有的移动、技能、交互等领域能力。HaloDebug 负责观察与显式调试操作，不拥有这些领域的正式玩法规则。

## 配置和状态分别由谁拥有

| 对象      | 共享内容                                        | 独立内容                                                         |
| --------- | ----------------------------------------------- | ---------------------------------------------------------------- |
| AstraAI   | Modifier、Group、Behavior 与默认原生 Logic 配置 | 每 NPC 的应用、机会、冷却、执行数据；需要时创建的活动 Logic 实例 |
| Input     | Setup、Action、IMC 与 Handler 配置              | 每 Controller 的绑定关系、通道缓存；领域自己的动作状态           |
| HaloDebug | 公共绘制、控件与窗口类型                        | 当前世界的窗口实例、选择、调试会话与采集数据                     |

“资产可内嵌编辑”不等于“每个角色都会复制”。Input Handler 是共享对象，不能保存玩家运行状态；AstraAI Generator 则按每 NPC 复制，负责自己的订阅。应按类型职责判断所有权，不按一个统一口号处理。

## 开始操作前，先完成接入

AI Setup 通过 Provider 交给 Controller，异步加载后进入 Ready 再启动组合决策。InputManager 等本地玩家和 InputComponent 就绪，再应用配置。调试窗口读取实际已建立的状态，不应替代这些初始化步骤。

发现“手动补值或延迟一下就好了”时，先追踪入口、就绪通知与上下游调用。能够绕开症状，不等于已经找到了原实现缺陷。

## 结束一次执行，要释放自己拥有的资源

AstraAI Logic 负责本次任务的取消与清理；Input 配置退出解除它的使用关系并清缓存，具体技能或移动按所属领域结束；HaloDebug 窗口 Shutdown 解除自己的订阅。

异步回调使用原执行身份或领域自己的请求身份。不要让一次旧任务的完成，结束一个后来启动的新任务。
