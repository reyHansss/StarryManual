## 它解决什么问题

一个 NPC 在任何时刻都要回答“现在做什么”。StellaUtilityAI 把这个问题拆成四件事，分别交给不同的对象：

- **现在有哪些机会**：Objective 保存当前事实，例如“有可接取的命令”“我在分配区域之外”。
- **我能做哪些事**：Modifier 一层层叠加出这个 NPC 当前可用的行为集合，例如“基础反应 + 人形战斗 + 持火把”。
- **哪件事最值得做**：Behavior 判断能否开始，并给机会打分；选择器按优先级与分数选出一个。
- **这一次具体怎么做**：被选中行为的 Logic 负责执行，可以直接调用移动、技能，也可以交给行为树、状态树或 HTN。

这样，“行为配置”可以像积木一样按角色、状态、区域叠加和撤销，而“执行”只关心这一次动作的开始、取消和清理。

## 核心概念

<Terms />

主决策组件是 Controller 上的 `UStellaUtilityAIComponent`，Objective 由同一个 Controller 上的 `UStellaUtilityAIObjectiveComponent` 管理。两者分开：Objective 只维护事实，不选择行为。

## 资产与创建位置

在内容浏览器中右键，选择 **AI → StellaUtilityAI**，可以创建以下资产。菜单项名称带有对应的缩写：

| 前缀     | 菜单项                            | 用途                                 | 编辑方式                                                      |
| -------- | --------------------------------- | ------------------------------------ | ------------------------------------------------------------- |
| `AIBM_`  | Behavior Modifier (AIBM)          | 一层行为增删配置                     | 蓝图资产，打开后自动切到“Behavior Modifier”页签进行可视化编辑 |
| `AIBMS_` | AIBehaviorModifierStack (AIBMS)   | Modifier 类的有序列表                | Stack 编辑器，带最终组合的只读预览                            |
| `AIB_`   | Behavior (AIB)                    | 自定义 Behavior 类型：激活条件与评分 | 蓝图类；具体节点的参数在 AIBM 中填写                          |
| `AIBG_`  | Behavior Group (AIBG)             | 自定义 Group 类型：候选筛选条件      | 蓝图类；组参数在 AIBM 中填写                                  |
| `AIBL_`  | BehaviorLogic (AIBL)              | 需要事件图或 latent 节点的蓝图 Logic | 以 BlueprintBase 为父类的蓝图                                 |
| `AIO_`   | Objective (AIO)                   | 自定义机会数据                       | 蓝图类                                                        |
| `AIOG_`  | Objective Generator (AIOG)        | 自定义机会生成器                     | 蓝图类                                                        |
| `AIOCS_` | AIObjectiveComponentSetup (AIOCS) | 生成器模板列表                       | 数据资产                                                      |
| `AIC_`   | Command (AIC)                     | 可发布、领取和结束使用的命令类型     | 蓝图类                                                        |

Modifier 里的 Group、Behavior、Logic 都是配置模板，所有使用这套配置的 NPC 共享同一份对象。每个 NPC 只单独保存运行时的数据，例如应用句柄、评估结果、冷却和当前执行。

## 在 Starry 中怎样接入

Starry 通过 `AStarryAIController` 接入 StellaUtilityAI，配置入口是角色的 AISetup：

1. 在 **Starry → AI → Starry AI Setup** 创建 `UStarryAISetupDataAsset`，选择 `BrainType = Composition`，填写 `ModifierStack` 与 `ObjectiveSetup`。
2. 在 `AStarryAICharacter` 的派生类上设置 `AISetup`。

**Controller 装配的顺序：**

1. 异步加载 AISetup；
2. 创建感知组件；
3. 创建并初始化 Objective 组件；
4. 创建 `UStellaUtilityAIComponent` 并初始化；
5. 进入 `Ready`，广播 `OnAISetupComplete`，开始组合决策。

完整过程见[游戏框架 · 一局游戏怎样启动](/read/framework-startup#ai-控制器怎样装配)。

**装配时要注意：**

- **只在权威端运行**：客户端（`NM_Client`）世界不装配 AI 决策。
- **等就绪信号**：依赖 StellaUtilityAI 的功能应等待 `OnAISetupComplete`，或先检查 `HasCompletedAISetup()`，不要假定角色一生成就已就绪。
- **自定义配置来源**：自定义 Pawn 可以通过 `IStarryAISetupProviderInterface::GetAISetupData` 提供配置。
