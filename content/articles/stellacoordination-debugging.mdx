## Coordination 面板

在非 Shipping 构建的 PIE 或游戏中按 **F1** 切换调试输入，从顶部菜单打开 **AI → Coordination**。面板查看整个世界的协调宿主：

- **只在权威世界有数据**：客户端世界不运行群体协调，面板只显示提示，也没有向服务器查询的通道。
- **跟随 StellaDebug 的选择**：它读取 StellaDebug 顶栏的当前选择，不使用 Agents 窗口的观察对象。
- **只读**：面板不调用任何条件、代价项或准入判断，显示的结论都来自宿主实际经过的判断。

**顶部**：实例数、配额池数与宿主时钟；“场景绘制”控制是否在视口中绘制，“跟随选择”控制是否随选择切换实例。

**实例列表**：实例、模式、键对象、成员数与群体树激活路径。勾选“跟随选择”时，选中某个实例的成员或键对象，面板就定位到这个实例；点击列表行则固定选择。

**选中实例**：

- **概况**：键对象、共享目标、群体树运行状态、距离下次更新的时间，以及最近一次配对是多久之前。
- **成员战术**：成员贡献的战术，按“标签 → 子树（贡献者）”列出；被后加入者覆盖的项置灰并标注。
- **职责需求**：职责（带需求编号）、容量、优先级、担任人数、目标、分配设置（保持优势、冻结、一次性已分配、已耗尽、按组）、成员条件，以及代价项与权重。没有代价项时显示“到目标距离”。
- **候选评估**：最近一次配对中每名成员对每项需求的评估，读法见下文。
- **未结束的安排**：序号、成员、职责、状态、已报告的进度、代持配额（持有，或排队及阻挡原因），以及已投递未采用的时长。

### 读懂候选评估

- **数字**：代价，越小越优先。
- **★**：本次配对选中。
- **保持**：原担任者，配对时扣除了保持优势。
- **组名**：成员名后的方括号是组织事实来源给出的组名。
- **不可担任的原因**：显示在格子里，例如冷却中、标签不符、冻结中；成员条件不满足时显示条件的类名。原因的含义见[配对与分配设置](/read/stellacoordination-pairing#一次配对怎样进行)。
- **不参与配对**：不可指挥或不可用的成员单独标注，整行不参与配对。

把鼠标悬停在格子上可以看到更多：

- **逐项代价**：每个代价项按“代价项 × 权重 = 值”列出；没有代价项时显示到目标的距离。冻结需求的担任者标明固定担任、不重新评估。
- **未选原因**：已担任其他职责；名额已被优先级更高或代价更低的成员占满；按组捆绑时，同组成员须全部可担任且放得下。

### 配额池与时间线

**配额池**：每个池显示“池 @ 作用域 · 占用 / 容量”，列出持有者与排队者、权重、已等待时长和阻挡原因。阻挡原因有三种：

- **容量不足，等待持有者归还**；
- **前有排队**；
- **本池放得下，等待其他池**：同一申请中的其他池还放不下。

**安排时间线**：记录实例创建与结束、成员加入与离开、安排的提出、投递、采用、开始、进度、请求停止与结束（详情为结束原因），以及职责耗尽。

- **持续记录**：面板关闭时也在记录，最多保留 512 条。
- **筛选与清空**：可以只看选中实例，也可以清空。
- **记录起点**：StellaDebug 接入当前世界后才开始记录，此前发生的配对与事件不会补记。

| 红   | 停止中 |

## 按现象排查

| 现象                       | 先检查                                                                                                                                                          |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 面板没有数据               | 是否在客户端世界查看；协调只在服务器或单机世界运行                                                                                                              |
| 成员不在实例中             | 是否已登记；入组是否被拒绝：参与者不可用、模式没有群体树，或它已在别的实例中且新请求的优先级不更高                                                              |
| 实例突然结束               | 键对象是否死亡或销毁；成员是否全部离开；群体树是否停止                                                                                                          |
| 没有职责需求               | 群体树是否编译并保存；职责任务是否在当前激活路径上，而不是兄弟状态上                                                                                            |
| 成员没被选中               | 候选评估中的不可担任原因；悬停看未选原因：名额被优先级更高或代价更低的成员占满                                                                                  |
| 安排停在“已提出”           | 代持配额是否在排队及阻挡原因；成员是否还有等待停止确认的旧安排                                                                                                  |
| 已投递，随后变为“未采用”   | 投递方式是否和成员的决策匹配。StellaUtilityAI 成员看 Objectives 面板里有没有命令机会、Behavior 能否找到命令；StateTree 成员是否在 `OfferTimeout` 内进入持有状态 |
| 一直“停止中”               | 执行侧是否发现停止请求并报告结束：Logic 的 `IsExecutionValid` 是否检查命令 `IsAvailable()`，成员树的持有任务是否还在运行                                        |
| 同一名成员反复失败又被选中 | 失败与未采用之后有 `OfferTimeout` 的冷却；冷却结束后条件仍然满足，就会被再次选中                                                                                |
| 职责意外耗尽               | 职责任务的耗尽设置；时间线中的结束（失效）与职责耗尽事件                                                                                                        |
| 换人太频繁，或该换人时不换 | 保持优势是否合适；代价项的权重                                                                                                                                  |

记录问题时，同时写下实例编号、成员、职责、安排序号、当时的状态与结束原因，方便判断是配对、投递还是执行侧的问题。

## 调试接口

需要自己做统计或工具时，可以使用宿主与配额服务的调试接口。它们只在非 Shipping 构建中提供，类型位于 `StellaCoordinationDebugTypes.h`：

| 接口                                                                                             | 内容                                                                                                     |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `UStellaCoordinationSubsystem::OnDebugSolved`                                                    | 每次配对后的决策解释：需求、每名成员的配对资格、对各需求的评估结论与逐项代价、组名、配对前担任与本次选中 |
| `UStellaCoordinationSubsystem::OnDebugEvent`                                                     | 实例、成员与安排的状态变化，以及职责耗尽，带宿主时钟、安排身份、成员或键对象、职责、进度与结束原因       |
| `GetDebugInstances`／`GetDebugAssignments`／`GetDebugTime`                                       | 当前实例、某个实例未结束安排的副本、宿主时钟                                                             |
| 实例的 `GetDebugActiveStates`／`GetDebugTreeStatus`／`GetDebugNextUpdateTime`／`GetDebugMembers` | 群体树激活路径、运行状态、下次更新时刻，以及按加入顺序排列的成员记录（含贡献的战术）                     |
| `UStellaCoordinationQuotaSubsystem::GetDebugPools`                                               | 各池的占用、持有者与排队者，排队者带已等待时长和阻挡原因                                                 |

- **只在有订阅时构造**：没有订阅时，宿主不构造调试数据。
- **同步通知，按值保存**：两个委托都是同步通知，观察者不得在回调中修改宿主；需要历史时，由订阅方按值保存。

**在 StateTree 调试器中辨认群体树**：协调实例对象按“模式名*键对象名*实例身份”命名，引擎 StateTree 调试轨迹以这个名字作为实例名。在编辑器 StateTree 调试器中实际查看群体树，没有经过验证。
