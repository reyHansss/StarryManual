# 点阵输入与知识图谱更新记录

## 2026-10-26：修复间歇性扰动减弱，减少图谱重复更新

用户反馈知识图谱响应偏慢，首页点阵在正常运行一段时间后会突然几乎不响应鼠标，稍后恢复。

### 已复现的问题

`components/particle-effects.tsx` 原先在每条指针事件里计算速度，但把间隔下限固定为 16 毫秒。事件频率高于绘制频率时，事件间位移变小，分母却不会相应减小；随后到达的同坐标事件还会把速度直接覆盖为零。

在真实输入监听与 RAF 的隔离测试中，同样以 1000 CSS 像素／秒移动，60 次／秒输入在绘制前衰减后约为 890，960 次／秒约为 58；每帧末尾补一条同坐标事件时，读数变为零。它能复现“仍在划动但扰动很弱”的输入失效，不据此认定用户遇到的所有间歇卡顿都来自同一原因。

### 实现

- 指针事件保存最新坐标，绘制帧按两帧之间的实际位移与时间计算速度；同帧的同坐标事件不会抹掉此前位移。
- 保留速度上限、停手衰减、原有粒子展开与慢回位算法、触摸短脉冲、全局暂停、减少动态效果、离屏／后台停帧和卸载清理。
- `components/knowledge-graph.tsx` 仅在选择或操作入口变化时更新节点数据；位置帧复用连线与回调，并按节点数据记忆化内容。位置由 React Flow 外层处理，缩放仍通过原有订阅更新圆点与标题。
- `components/use-graph-motion.ts` 保留没有位移的节点引用，保持拖动节点直接跟随输入；不改变弹力、布局和有限余动规则。

### 验证

- `pnpm test:particles`：5 项通过，覆盖 60／120／960 次／秒输入、同坐标事件、12 轮快慢划动与停帧再唤醒、触摸、后台／离屏恢复、暂停及清理。旧源码执行相同用例时 3 项失败，修复后全部通过。
- `pnpm test:graph`：12 项通过，包含布局、局部关系、缩放尺寸、牵引和有限余动，以及位置更新复用引用、选择不重置拖动坐标。
- 对三节点执行 60 次位置更新的隔离计数：节点数据重建从 180 次降至 0，连线数组和手势回调各从 60 次降至 0。这里只计数组与对象引用变化，不是浏览器实际渲染次数或 FPS 测量。
- `pnpm typecheck` 与 `/StarryManual` 静态构建通过；`pnpm check:pages` 检查 40 个 HTML、32 篇文章和 3379 处本地资源／链接，无失效引用。
- 本地静态页面在约 972 × 742 CSS 像素视口中复查了点阵拨动、暂停与恢复，模块图拖动牵引、滚轮缩放、选择后位置保持，以及全部文章和局部图入口；缩放后标题正常恢复。
- 新增粒子测试接入现有 Pages 工作流，沿用本地修改与验证的范围，未推送或发布。

### 验证边界

输入测试替换了 Canvas 绘制以隔离事件采样，组件测试替换了 React 调度以检查交给 React Flow 的数据；实际绘制和手势另由浏览器复查。未对用户鼠标的真实报告率、长期运行或不同 GPU／浏览器做性能采样，不能把引用计数直接换算为帧率收益。

构建仍有 Fumadocs 搜索样式 `::highlight` 的两条优化器警告，测试仍有 Node 对现有 TypeScript 模块类型声明的提示，均未导致本次检查失败。
