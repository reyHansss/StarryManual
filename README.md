# Starry手册

一个面向读者和创作者的文档体验 demo。包含文章阅读、由文章链接生成的知识图谱、浏览器交互实验、UE 蓝图节点查看和本地网页编辑。

这是独立内容、独立 Git 仓库。所有示例文章均为本仓库新写的教学内容，用于评估站点技术与阅读体验，尚未形成 Starry 的正式功能手册。

## 运行

环境：Node.js 22.18+（推荐 24 LTS）、pnpm 11。本机已用 Node.js 24.19.0、pnpm 11.25.0 安装验证。

```powershell
Set-Location 'C:\Users\34200\Documents\Unreal Projects\Starry\Starry手册'
pnpm install
pnpm dev
```

访问 <http://127.0.0.1:3210>。开发服务绑定本机回环地址，适合这份本地演示的网页编辑模式。

```powershell
pnpm typecheck
pnpm check:content
pnpm test:blueprint
pnpm test:graph
pnpm build
pnpm start
```

`pnpm start` 使用生产构建，只展示已构建的文章版本。编辑内容后，开发模式会重新编译；生产模式需要重新构建再启动。

## GitHub Pages 静态发布

站点：<https://reyhansss.github.io/StarryManual/>。独立仓库：<https://github.com/reyHansss/StarryManual>。

推送到远端 `main` 分支后，GitHub Actions 会安装锁定的依赖，检查格式、文章与类型，再构建、检查并发布静态站点。工作流位于 `.github/workflows/pages.yml`，发布状态见 <https://github.com/reyHansss/StarryManual/actions>。也可在 Actions 中手动运行“发布 Starry手册”。

内容更新后提交并推送即可，无需在本地生成或提交 `out/`：

```powershell
git add .
git commit -m '更新手册内容'
git push origin HEAD:main
```

Pages 的发布源使用 GitHub Actions。构建通过 `actions/configure-pages` 读取实际部署路径，产物仅上传 `out/`，部署任务使用 GitHub 自动提供的短期凭证，无需额外保存个人 Token。

如需在本地预览同样的发布结果：

```powershell
pnpm build:pages --base-path /StarryManual
pnpm check:pages
pnpm preview:pages
```

访问 <http://127.0.0.1:3211/StarryManual/>。预览服务只读取 `out/` 中的文件，提供目录首页与真实 404，不调用 Next.js 服务，也不使用首页回退来补救失效路由。

`out/` 就是待发布的完整目录，含预生成 HTML、浏览器脚本、样式、蓝图资源与 `.nojekyll`。实际发布时将该目录交给 GitHub Pages；仓库项目站点的 `--base-path` 必须与仓库名一致。若使用 `用户名.github.io` 或独立域名的根路径，运行不带参数的 `pnpm build:pages`。路径在构建时确定，不能只移动文件后修改。

线上保留文章阅读、全文搜索、知识图谱、交互实验和蓝图渲染。网页编辑器继续通过本机 `pnpm dev` 使用；发布构建排除 Keystatic 页面和 API，也隐藏对应编辑按钮。可在本地文件或本地网页中修改同一份 MDX，再提交推送；也可在 GitHub 文件编辑器中修改 MDX，提交到 `main` 后同样触发发布。若需要发布站点内的在线可视化编辑后台，需另行提供身份验证和 API 托管。

`pnpm build` / `pnpm start` 是原有的 Next 服务模式；`pnpm build:pages` / `pnpm preview:pages` 是静态发布与验证模式。执行静态构建后，如需使用 `pnpm start`，先重新运行 `pnpm build`。本地创作推荐直接运行 `pnpm dev`。

站点使用 GitHub Pages 默认域名；仓库公开，网页中的文章和静态资源也面向公开访问。

## 修改内容

- 本地文件：编辑 `content/articles/*.mdx`。
- 网页编辑：打开 <http://127.0.0.1:3210/keystatic>，选择“文章”，编辑并保存。
- 文章标题、简介、主题和阅读顺序同时用于导航、搜索与图谱。
- 正文中的 `/read/文章标识` 链接生成图谱连线、前往页面和反向链接。
- 新文章使用英文小写网址标识，修改标识或删除文章时同步维护引用；运行 `pnpm check:content` 核对。
- 网页编辑器支持插入“说明卡片”“自动排版图表”“输入缓冲交互实验”“蓝图节点查看器”。本地 MDX 对应 `Note`、`Diagram`、`InputBufferDemo`、`BlueprintDemo`。
- MDX 不写 `import` 或随意的 HTML；新组件应在 `components/mdx.tsx` 和 `keystatic.config.ts` 同步注册，保证两种编辑方式可以往返。

## 笔记与图表创作原则

用户于 2026-10-17 明确要求后续笔记快速成稿、方便修改。日常只需编写正文、图表关系与数据，布局、样式和交互由自动布局或共享模板处理，避免每篇笔记反复调坐标、连线和页面代码。普通内容更新做必要检查，新增模板、组件或出现显示问题时再做相应的视觉调整。

图表按项目笔记需要选择，用于说明架构依赖、流程、时序、生命周期、状态、数据关系等。Archify 仅作为丰富度和交互效果的参考，不是必须接入的工具；具体实现以生成速度、可读性和维护成本为依据。

当前正文使用共享 `Diagram` 组件，把 Mermaid 文本自动排成图表；架构导览、运行与生命周期、输入缓冲分别提供关系、状态和时序示例。图表靠近视口时才加载渲染器，颜色、字体和圆角由共享主题提供。作者不必手动布局，语法出错时可以直接查看源码；新图种首次使用时检查一次模板，日常同类内容直接复用。

所有正文图表支持直接滚轮缩放、左键平移、触屏单指平移与双指缩放，工具栏提供缩放、适应画布、重置和全屏查看。默认视图保留可读字号；适应画布显示完整图表，全屏退出后恢复原有视图和正文位置。键盘聚焦画布后可用 +/− 缩放、方向键平移、F 适应、0 或 Home 重置；全屏按 Esc 返回。文章只填写原有标题与图表文本，不增加交互字段。

| 要解释的问题                   | 优先表达方式             |
| ------------------------------ | ------------------------ |
| 接下来可以读哪篇文章           | 文章知识图谱与局部图     |
| 哪些模块协作、谁拥有或依赖谁   | 关系图、架构图           |
| 经过哪些步骤、在哪个条件分支   | 流程图                   |
| 谁先调用谁、等待和返回发生在哪 | 时序图                   |
| 启动、完成、取消、清理如何转换 | 状态图                   |
| 对象或数据实体怎样关联         | 类型关系图、ER 图        |
| 参数变化如何影响过程           | 可复用交互实验或数据图表 |

知识图谱不替代技术图表，技术图表中的箭头应明确表示调用、依赖、数据或状态转换。Mermaid 之外的图种和复杂交互，按实际笔记需要增加共享组件。

## 演示功能

| 页面                    | 可操作的内容                                                               |
| ----------------------- | -------------------------------------------------------------------------- |
| 首页 `/`                | 阅读路线、文档关系预览、快速入口                                           |
| 阅读 `/read/start-here` | 主题导航、页内目录、前往和引用文章、编辑本页                               |
| 图谱 `/graph`           | 全局与主题图、节点局部图、路径返回、节点搜索、节点拖动、平移缩放和阅读跳转 |
| 实验 `/lab`             | 调节输入时间和有效期、播放时间线、观察消费与过期、重置                     |
| 蓝图 `/blueprint`       | 本地渲染节点与连线、平移缩放、粘贴节点文本、恢复样例                       |
| 编辑 `/keystatic`       | 编辑本地文章及其元信息，保存到同一份 MDX                                   |

顶部搜索支持 Ctrl K，并检索文章标题、简介和正文。

知识图谱参考 Obsidian 的关系空间：完整图使用按文章主题着色的圆点，关联越多的节点略大。初始位置由关系自动计算；左键拖动时关联节点通过弹力跟随，松手后平滑回稳，静止后停止物理计算。空白平移、直接滚轮缩放，也可切换到按主题排列或重新排列节点。选择其他节点会保留已有位置；切换图谱范围、搜索、布局、更新图谱内容或刷新会重新计算当前视图。减少动态效果时保留直接拖动，关闭牵引与余动。

- 全局图展示全部文章；主题按钮根据现有分类生成主题子图。
- 选择节点后，点击节点下方的图谱图标或右侧“进入局部图谱”。局部图显示中心文章及直接相连的页面，同时保留邻居之间的链接；正向、反向与跨主题关联都纳入。
- 右侧的相连页面可继续进入另一篇文章的局部图。顶部路径与返回按钮回到主题或全局，文章箭头单独负责阅读跳转。
- 图谱搜索按当前范围筛选标题和简介。搜索定位到一篇文章后进入局部图，会清空搜索并展开完整邻域。
- 当前范围与搜索保存在网址查询参数中，例如 `/graph/?center=input-buffer` 或 `/graph/?category=architecture&center=runtime`，可直接打开、刷新与分享，也支持浏览器前进和后退。这些行为由浏览器完成，静态部署继续适用。

新增或修改笔记时只维护原有分类和正文链接，图谱与局部图随之生成，不增加逐篇配置。拖动结果不写回 MDX，首页继续使用精简卡片预览。

## 技术组成

Next.js 16 App Router 与 React 19 提供站点和组件；Fumadocs MDX/Core/UI 提供文章编译、目录与 Markdown 表达；Keystatic 管理本地 MDX；React Flow 显示文章关系，d3-force 提供按需牵引；Mermaid 自动排版正文图表；blueprintUE 前端渲染器显示 UE 节点。依赖版本与锁文件随仓库保存。

内容读取仅扫描本仓库 `content/articles`。静态资源在本仓库 `public`，没有导入父目录文章或资产。父仓库使用其本地排除规则忽略整份手册目录；本仓库的 `.git` 独立管理手册代码与内容。

## 当前边界

- 示例内容展示信息组织方式，不能视为项目接口文档或功能验收。
- 交互实验是单输入的浏览器规则模型，没有接入 UE 运行时、真实技能或网络。
- 蓝图内置文本为手写教学样例；渲染器不执行蓝图、不直接读取 `.uasset`。复杂自定义节点、其他图表类型和实际 UE 5.8 导出的兼容性需用目标资产进一步验证。临时粘贴只在当前页面保留，最大 200 KB。
- Keystatic 当前采用本地文件存储，编辑时不自动 Git 提交，也不执行远端推送。GitHub Pages 自动构建发布已配置；在线编辑身份认证与 Keystatic GitHub 存储尚未配置。
- 知识图谱表示文章阅读关系，连线不表示程序调用或模块依赖；局部图是文章的一跳阅读邻域，节点位置由前端自动布局。
- 当前内容规模为八篇示例，尚未验证大规模图谱性能。主题和组件种类由代码统一注册，日常文章内容可从网页编辑。

## 手册动效（2026-10-17）

参考 Emil Kowalski 的 [emil-design-eng](https://github.com/emilkowalski/skills/blob/2d228630ba1446365f614a108cb8252f1feda202/skills/emil-design-eng/SKILL.md)、[animate](https://github.com/emilkowalski/skills/blob/2d228630ba1446365f614a108cb8252f1feda202/skills/animate/SKILL.md) 与其 Recipes：先根据用途与使用频率决定是否使用动效，再确定实现、时长和缓动。动效用于表达操作反馈、选中状态和实验结果，正文阅读保持稳定。

- 首页的标签、标题、介绍、操作区与图谱使用短间隔进场，三张入口卡片依次淡入。使用 CSS `@starting-style`，不支持该特性的浏览器直接显示内容，不依赖客户端脚本解除隐藏。
- 共享按钮提供 120 ms 的轻微按压反馈；支持精细指针悬停时，入口卡片小幅抬起、箭头移动。键盘操作跳过按压缩放，首页的键盘导航也跳过进场过渡。
- 图谱节点选中时，边界、光环和关联连线用 160 ms 过渡强调，详情摘要短暂淡入；详情操作按钮不因摘要更新而重新挂载，保持操作焦点。键盘选择立即显示结果。文章关联不再使用持续流动的虚线。
- 输入缓冲实验的等待、消费和过期图标平滑切换，结果面板同步改变强调色。播放游标使用 transform，不再逐帧修改 left，也不额外给时间线添加跟随延迟。
- 系统设置为“减少动态效果”时，跳过首页的位移进场、控件缩放与悬停位移，隐藏移动游标；保留结果文字、数值和较轻的透明度与颜色反馈。搜索面板及文章正文直接显示。

缓动和时长集中维护在 `app/motion.css`，没有新增动效依赖。后续笔记与文章内的实验组件自动复用这些效果，创作时不需要填写动画参数。
