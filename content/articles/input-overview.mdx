## 输入经过哪几层

Starry 的玩家输入建立在 UE 的 Enhanced Input 之上，在它后面加了一层**项目分派**。

**Enhanced Input 负责**

- **Input Action（IA）**：定义一个动作和它的值类型，以及动作自身的修饰器与触发器。
- **Input Mapping Context（IMC）**：把设备按键映射到 Action。

**项目分派层负责**

- **Input Setup**：把一个 IMC、优先级和若干 Handler 组织成一份可以整体增删的配置。
- **InputManager**：`UStarryInputManagerComponent` 应用这些配置，为每个 Action 的事件绑定一次，再分派给登记的 Handler。
- **Input Handler**：收到事件后调用实际的能力，比如移动、技能或界面。
- **输入缓存**：在动画指定的窗口内把可缓存的输入延后执行。

## InputManager 挂在 Controller 上

InputManager 只能挂在 PlayerController 上，不支持挂在 Pawn 上，所以它可以随 Controller 跨角色复用。`AStarryPlayerController` 已经创建了默认的 Manager。Manager 本身继承了输入缓存组件，基本的缓存不需要再挂第二个组件。

**配置从这四个地方来：**

| 配置来源            | 填写位置                                                            | 适合什么                   |
| ------------------- | ------------------------------------------------------------------- | -------------------------- |
| Controller 固定配置 | Manager 的 `InputHandlerSetup`                                      | 跟随本地玩家一直存在的输入 |
| 角色配置            | `UStarryCharacterData::InputSetups`，由玩家角色的 Provider 接口提供 | 随角色切换的移动与角色能力 |
| 功能配置            | `GameFeatureAction_AddInputBinding::InputSetups`                    | 随功能进入与退出成对增删   |
| 辅助映射            | Manager 的 `StandaloneContexts`                                     | 不需要 Handler 的辅助 IMC  |

- **角色配置**：由 Manager 统一应用。角色数据就绪时，Hero 组件请求 `RefreshPawnInputSetups`，角色自己不再保存第二份配置记录。
- **避免重复拥有**：不同来源之间不要重复拥有同一份 Setup 或同一个 IMC，详见[配置与生命周期](/read/input-binding)。

## 初始化要完整

`AStarryPlayerController` 在 `SetupInputComponent` 调用完基类之后执行 `InitializeInput()`。自定义 Controller 时保留同样的顺序。

初始化需要 LocalPlayer、Enhanced Input Subsystem 和 Controller 的输入组件都已就绪，输入组件必须是 `UEnhancedInputComponent`。目前没有“输入组件在运行中被重建后自动恢复”的机制。

`Config/DefaultInput.ini` 中与输入相关的设置：

```ini
DefaultPlayerInputClass=/Script/StarryGame.StarryPlayerInput
DefaultInputComponentClass=/Script/EnhancedInput.EnhancedInputComponent
bEnableUserSettings=True
UserSettingsClass=/Script/StarryGame.StarryInputUserSettings
DefaultPlayerMappableKeyProfileClass=/Script/StarryGame.StarryPlayerMappableKeyProfile
```

修改时保留这些项所在的配置节与其他内容。

## 项目设置与输入设备模式

**项目设置 `UStarryInputSettings`**

- **`TrackedEvents`**：决定 Manager 为每个 Action 绑定哪些触发阶段，默认五种都绑。
- **Handler 屏幕调试**：仅在编辑器中可用。

**输入设备模式**

- Manager 根据最近使用的设备判断当前是键鼠、手柄还是触控，查询函数为 `IsUsingKeyboardAndMouse`、`IsUsingGamepad`、`IsUsingTouch`。
- 模式用 `Input.Mode.*` 标签表示。变化时广播 `OnInputModeChanged`，并通过 `IStarryInputModeAwareInterface` 通知 PlayerController、HUD 与 Pawn。
- 输入模式只复制给拥有者。

`UStarryInputFunctionLibrary` 提供在蓝图中取得 Manager、缓存组件等的工具函数。
