## 发布不等于执行

命令（Command）是一份“谁符合条件谁就可以来做”的任务，发布后要经过三步才会真正执行：

1. 命令生成器把它变成 NPC 可以看到的机会；
2. Behavior 判断值不值得接；
3. Logic 真正开始执行时才领取它。

只发布命令，而 AI 一侧没有对应的生成器、Behavior 与 Logic，NPC 不会凭空移动、放技能或交互。

## 接取要求

命令的 `Requirements`（`FStellaUtilityAICommandRequirements`）决定谁可以接：

| 字段            | 含义                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------- |
| `Duration`      | 有效期，单位为游戏时间秒。`-1` 表示不限，正数为有效期，其他值会被拒绝                    |
| `Radius`        | 接取范围，单位厘米。`-1` 表示不限范围，非负值以 `Center` 为球心                          |
| `Center`        | 世界坐标，配合 `Radius` 定义接取范围                                                     |
| `TagQuery`      | 对接取者 **Pawn** 的标签查询；空查询表示不限制                                           |
| `AllowedActors` | 显式允许的 Pawn 列表；为空不限制，非空时与其他要求同时生效。按弱引用保存，不延长角色寿命 |

- **数值合法性**：`Duration` 与 `Radius` 必须是有限值，`Center` 不能含 NaN。
- **半径检查**：候选阶段的 `CanTake` 和正式的 `Take` 都会检查半径；领取之后走出范围，不会仅因为这一条就自动取消。需要持续约束时，由 Logic 或实际任务处理。
- **配置固定**：发布时会复制一份具体配置，发布后不再修改。需要变化时，结束旧命令并重新发布。

## 用蓝图发布

使用异步节点 **Issue AI Command**（`UStellaUtilityAIAsyncIssueCommand`）：

1. 传入有效的 `AAIController` 和命令类，可选地传入一个同类型、尚未发布的初始化对象。
2. 在初始化对象上发布之前，用 `SetRequirements`／`SetAllowedActors` 设置接取条件。
3. 先连好需要的输出事件，再根据实际结果处理后续流程。

| 输出事件              | 何时触发                                                |
| --------------------- | ------------------------------------------------------- |
| `OnCommandRegistered` | 命令发布成功                                            |
| `OnCommandTaken`      | 某个角色领取了命令，`User` 为这个角色                   |
| `OnCommandFinished`   | 某个角色以成功或失败结束了使用                          |
| `OnCommandReturned`   | 某个角色以 Aborted 结束使用，包括命令被撤销或超时的情况 |
| `OnCommandTimeout`    | 命令超过有效期。撤销没有专门的事件                      |
| `OnFailed`            | 发布失败；失败时不会先触发 Registered                   |

Taken、Returned、Finished 按**每个实际使用的角色**分别触发：一个角色完成，不代表其他角色也结束了使用。所有使用都结束后命令退役，异步节点随之自动结束订阅。

**权威端要求**：发布、`Take`、`EndUse` 和撤销都要在服务器或单机的权威世界执行。发布节点会检查 Controller 的权威，命令子系统拒绝客户端世界；在客户端调用不会自动发 RPC。`EndSubscription` 只停止当前监听者接收事件，不撤销命令。

## 完成与归还的区别

| `EndUse` 的结果     | 通知     | 之后这个角色能否再接这条命令 |
| ------------------- | -------- | ---------------------------- |
| Succeeded 或 Failed | Finished | 不能，记为已完成             |
| Aborted             | Returned | 可以                         |

- **撤销或超时**：命令被撤销或超时后，正在使用它的执行再调用 `EndUse`，一律按 Aborted 处理并发出 Returned。已经开始的执行仍要走正常的取消与清理，不能丢下任务引用就跳过归还。
- **会话结束**：NPC 的 StellaUtilityAI 会话结束时，它对命令的使用会自动按 Aborted 结束。

## AI 侧怎样接入

1. 把 `UStellaUtilityAIObjectiveGenerator_Commands` 加入 AIOCS 的 `GeneratorTemplates`。`SupportedClasses` 为空时接受所有命令类型，非空时只接受这些类型及其子类。
2. Behavior 用只读的 `CanTake` 评估机会，不要在评分时就 `Take`。
3. Logic 在 `Start` 中调用 `Take(Component, ExecutionId)`，把占用绑定到本次执行；在自己的 `Cleanup` 中配对调用 `EndUse(Component, ExecutionId, Result)`。

清理完成后才报告结束，可以避免“已经通知下一段流程开始，旧命令的资源却还被占着”。

## 有命令却没人执行

按顺序检查：

1. 发布是否收到 Registered；
2. 接取要求的交集是否为空；
3. 生成器的类型过滤；
4. Objectives 面板中有没有对应的机会；
5. Behavior 的分数；
6. Logic 的 `Take` 返回值。

排查工具见[调试与排查](/read/stellautilityai-debugging)，执行清理规则见 [Logic 与生命周期](/read/stellautilityai-logic)。

代码位置（插件 `Source/StellaUtilityAI`）：`Commands/StellaUtilityAICommand`、`Commands/StellaUtilityAICommandSubsystem`、`Commands/StellaUtilityAIObjective_Commands`、`Commands/StellaUtilityAIAsyncIssueCommand`。
