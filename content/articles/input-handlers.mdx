## Handler 是共享对象

Setup 的 `InputHandlers` 直接引用资产里的 Handler 对象。字段标成 `Instanced` 只是为了能在资产里直接编辑，运行时**不会**为每个玩家复制一份。所以：

- 不要在 Handler 的成员里保存当前玩家、按住计时、目标 Actor；
- 不要启动依赖这个对象身份的 latent 流程。

处理时从传入的 `Manager` 取得当前上下文，持续的状态放进所属的组件、技能或本次任务中。Manager 在同步调用前会设置当前 World，这也不代表 Handler 有了独立的玩家实例。

## 先选对事件

| Enhanced Input 事件 | 含义                                       | Handler 覆写的函数     |
| ------------------- | ------------------------------------------ | ---------------------- |
| `Started`           | 开始评估这次输入                           | `HandleStartedEvent`   |
| `Triggered`         | 触发条件满足                               | `HandleTriggeredEvent` |
| `Ongoing`           | 触发器仍在评估，还不等于触发成功           | `HandleOngoingEvent`   |
| `Completed`         | 已触发的输入完成                           | `HandleCompletedEvent` |
| `Canceled`          | 没有完成触发就结束，例如短按没达到长按阈值 | `HandleCancelledEvent` |

**选事件的规则**

- **持续输入**：现成的 Move 与 Look 处理器默认同时登记 `Triggered` 和 `Ongoing`。
- **短按、长按、释放**：要结合 Action 上的触发器来选事件。不能把 Ongoing 当成“每帧都成功触发”。

**登记与动态条件**

- **登记**：`InputActions` 与 `TriggerEvents` 决定 Handler 登记到哪些动作和事件。
- **`CanHandle`**：适合做静态匹配。
- **动态条件**：能不能移动、能不能转视角这类会变化的条件，放在处理函数里，或者 `CanMove`、`CanLook` 这样的领域判断中。

## 现成的处理器

| 需求                               | 处理器                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------- |
| 移动、鼠标视角、手柄视角           | `Move`、`Look`、`Look_Gamepad`                                         |
| 冲刺、步行、横移、瞄准             | `Locomotion`（显示名 Character: Locomotion，`IS_Locomotion` 正在使用） |
| 跳跃、蹲伏、自动奔跑               | `CharacterJump`、`CharacterCrouch`、`AutoRun`                          |
| 按技能的动态 InputTag 分派输入     | `AbilityInputTag`                                                      |
| 按类、标签或输入身份找技能并激活   | `AbilityClass`、`AbilityTag`、`AbilityInput`                           |
| 中断技能                           | `AbilityInterruption` 与 `InterruptAbilityClass`／`Tag`／`Input`       |
| 技能目标的确认与取消               | `AbilityTargeting`                                                     |
| 发送 GameplayEvent、HUD 事件、连招 | `GameplayEvent`、`HUDEvent`、`CombatCombo`、`DefaultHoldCombo`         |
| 在屏幕上打印调试文字               | `ShowDebugString`                                                      |

移动与角色动作经由项目的 Mover 接入。Traversal（翻越）通过角色接口提供，输入层本身不实现攀爬、翻越等动作。

## 移动方向与摇杆行为

**移动参考方向**

- **指定组件**：用 `SetForwardReference(USceneComponent*)` 指定方向来源组件，传 nullptr 可以清除。
- **指定旋转**：用 `SetForwardReferenceRotation(FRotator)` 直接指定旋转，它会覆盖当前的组件来源。
- **只取 Yaw**：读取接口只保留 Yaw，不会把 Pitch、Roll 带进平面移动。
- **默认方向**：没有有效的显式来源时，使用 Controller 的方向。
- **谁设置谁撤销**：切换角色不会自动清理所有显式方向引用，设置方向来源的一方要负责成对地设置和撤销。

**摇杆行为**：摇杆偏转怎样换算成速度与步态，由 `EStarryInputAnalogStickBehavior` 决定，可以用 `SetAnalogStickBehavior` 修改：

| 值                              | 行为                                     |
| ------------------------------- | ---------------------------------------- |
| `FixedSpeed_SingleGait`（默认） | 固定速度，移动强度不随摇杆偏转变化       |
| `FixedSpeed_WalkRun`            | 轻推为固定步行速度，推满为固定跑步速度   |
| `VariableSpeed_SingleGait`      | 偏转量控制速度，步行或跑步由步态输入选择 |
| `VariableSpeed_WalkRun`         | 偏转量控制速度，并按偏转量切换步行与跑步 |

Move 处理器的 `BlockMovementTags` 默认包含 `Input.Block.Movement`，带有其中任一标签时不移动角色。它还有一个最小输入幅度阈值，但对玩家角色几乎不起作用：玩家角色只要求输入幅度大于一个极小值。

## 技能输入与 GameplayEvent

- **`AbilityInputTag`**：把输入按 ASC 上技能 Spec 的动态 InputTag 送进输入队列。它和“找到一个技能类立刻激活”是两个入口，按技能的输入协议选用。
- **GameplayEvent**：通过 `Manager.SendGameplayEventToOwner` 发出。可以同时走本地与服务器两条路径，Listen Server 上本地只执行一次，远端 Controller 使用对应的 RPC。技能实际在哪一端运行，仍受 GAS 的 `NetExecutionPolicy` 约束。

同步返回值只反映这次调用当场发生的激活，不能用来判断服务器稍后通过 RPC 执行的结果。技能的失败、取消与完成，仍由 GAS 的通知或实际任务处理。

## 自定义一个 Handler

先在上表里找现成的能力，确实没有再派生：

1. 在内容浏览器 **Starry → Input** 下创建 Input Handler 蓝图，或在 C++ 中派生 `UStarryInputHandler`。
2. 设置它处理的动作与事件。
3. 在对应的 Handle 函数里调用领域接口。

不要在 Handler 中重复做按键映射、保存玩家实例，或另建一套输入调度。

输入值的变换见[修饰器与触发器](/read/input-triggers)，需要延后执行时见[通道输入缓存](/read/input-buffer)，多份 Setup 之间的分派规则见[配置与生命周期](/read/input-binding)。

代码位置：`Framework/Input/StarryInputHandler`、`Framework/Input/Handlers`、`Framework/Input/StarryInputTypes.h`。
