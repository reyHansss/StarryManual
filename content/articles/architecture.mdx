## 工程怎样分工

Starry 以 Unreal Engine 5.8 为基础。运行时代码主要位于 `StarryGame` 模块，内部按 `Framework` 与 `Gameplay` 区分可复用基础能力和具体玩法；`StarryEditor` 承担项目编辑器扩展，插件保留各自的模块边界。

`Framework` 提供角色、能力、输入、AI 接入、界面等基础能力，`Gameplay` 继承或组合这些能力实现项目玩法。基础框架不反向包含具体玩法的头文件。玩法型 GameFeature 可以使用项目框架，按自身功能归属组织，不与图中的通用插件混为一层。

## 按职责定位系统

下表中的 `Framework/` 与 `Gameplay/` 路径相对于 `Source/StarryGame`。这些是工程中的领域划分，详细使用章节会随整理进度补充。

| 领域          | 主要职责                                  | 代码位置                                                                                         |
| ------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 玩法装配      | 游戏规则入口、Experience 配置与功能激活   | `Framework/GameModes`、`Framework/Experience`、`Framework/GameFeatures`                          |
| 角色与表现    | 玩家、AI 与其他角色，移动接入、动画和相机 | `Framework/Character`、`Framework/Animation`、`Framework/Camera`                                 |
| 能力与战斗    | GAS 能力、战斗规则与项目战斗实现          | `Framework/AbilitySystem`、`Framework/Combat`、`Gameplay/Combat`                                 |
| 物品与交互    | 背包、装备、交互与阵营领域                | `Framework/Inventory`、`Framework/Equipment`、`Framework/Interaction`、`Framework/Factions`      |
| AI 与世界玩法 | AI 框架接入、生态运行与任务生命周期       | `Framework/AI`、`Gameplay/AI`、`Gameplay/Ecology`、`Gameplay/Missions`                           |
| 玩家体验      | 输入、玩家状态、界面、设置与前端          | `Framework/Input`、`Framework/Player`、`Framework/UI`、`Framework/Settings`、`Gameplay/Frontend` |
| 开发支持      | 调试入口、运行面板与编辑器扩展            | `Framework/Development`、`Source/StarryEditor`、`Plugins/Toolkit/HaloDebug`                      |

通用插件按自身职责维护。例如 AstraAI 提供行为组合与选择能力，项目 AI 目录负责角色、感知、具体玩法及调试接入。HaloDebug 提供绘制与工具基础，项目窗口负责解释各领域的实际状态。

## 配置、资源与运行状态

`Content` 保存角色、场景、美术、UI、配置蓝图及数据资产；`Config` 保存项目和引擎设置。`Content/Core` 用于系统级、全局共享一份的配置；角色、PawnData、Experience 等配置放在 `Content/Blueprints` 对应领域，资源目录不与 C++ 目录机械对应。

配置描述能力与规则，运行状态由实际宿主拥有。共享资产是否会实例化，应以类型的真实生命周期为准。例如 Input Handler 是共享配置，不能保存某个玩家的运行状态；AstraAI 的执行数据属于各自 NPC，蓝图 Logic 在实际执行时创建实例。

## 系统怎样协作

Experience 与 GameFeature 负责装配功能；角色、Controller、组件和各领域系统在自己的生命周期中接入。玩家输入经 Handler 调用移动、技能或交互，AI 经选中的 Logic 使用相应领域能力，具体玩法继续拥有规则、状态和资源。

结束或切换时，各使用方撤销自己的绑定、订阅和任务，领域系统处理自身状态与资源。异步回调使用原请求或执行身份，避免旧任务的结果影响后来的执行。

网络玩法遵循当前世界的 Authority，服务器能力不依赖 LocalPlayer、界面或本地玩家存档存在。本地输入与表现、权威规则和持久保存分别由相应系统负责。
