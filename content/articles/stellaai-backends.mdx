## 顶层选择，局部编排

StellaAI 决定当前做哪个 Behavior；Logic 可以把这一次动作交给 Behavior Tree、StateTree 或 HTN 去编排。

**后端组件**

- 后端组件挂在 Controller 上，按需创建并复用：每个 Controller 最多一个 Stella 的 BT 组件、一个 StateTree 组件、一个 HTN 组件，再加一个原生黑板。
- 这些组件可以独立使用，不持有 StellaAI 的执行身份。
- Logic 接收后端的结果，校验原执行 Id 后再结束本次行为。主 Brain 始终是 `UStellaAIComponent`。

**拒绝而不抢占**：Controller 上已经有同类的原生组件，或者 Stella 的后端正忙时，Logic 和任务直接失败，不抢占，也不创建第二个。

| Logic                                 | 配置                                              | 结束与结果                                                                  |
| ------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------- |
| `UStellaAIBehaviorLogic_BehaviorTree` | `BehaviorTree`、`ExecutionMode`                   | 单次运行时由 `FinishTree` 节点明确报告；树自然结束但没有报告结果，按 Failed |
| `UStellaAIBehaviorLogic_StateTree`    | `FStateTreeReference`（使用 AI Component Schema） | 按 StateTree 的结果完成，Stopped 记为 Aborted；不接管黑板                   |
| `UStellaAIBehaviorLogic_HTN`          | `UHTN`、`bLoop`（默认不循环）；HTN 必须有黑板     | 成功之外的结果一律记为 Failed；退出时等待后端安全停止                       |

HTN 后端由项目的 `UStellaAIHTNComponent` 承接，它是原生 HTN 组件的薄派生：只负责停止判断、单次与循环配置和清理。Controller 上已经有普通的 `UHTNComponent` 时，HTN Logic 直接失败。

## 行为树怎样报告结果

单次运行的 BT 在真正完成整次目标的位置放 `UStellaAIBTTask_FinishTree`，明确选择 `Succeeded`、`Failed` 或 `Aborted`。

- **结束范围**：它结束的是**整棵**当前 BT，不只是所在分支。
- **组件要求**：这个节点必须运行在 Stella 的 BT 组件里，否则返回 Failed。
- **嵌套调用**：如果 BT 是被 StateTree 的局部任务调用的，结果交给直接调用它的任务，不会越过父 StateTree 直接结束顶层行为。

不要在局部 BT 里调用 Controller 的 `RunBehaviorTree` 去替换主 Brain。

## StateTree 调用局部树

在 StateTree 中可以用 `FStellaAISTTask_RunBehaviorTree` 与 `FStellaAISTTask_RunHTN` 运行局部的 BT 或 HTN。单次任务配置 `bLoop = false`。

**任务退出（ExitState）**：

- 退出是同步的：任务先解绑，然后立即返回。
- 正常退出时，任务只是向子树发出清理请求，子树自己在后台完成中止，期间拒绝被复用。
- 宿主拆卸时，直接强制清理。

真正等待子 BT／HTN 清理完成的是外层的 StellaAI StateTree Logic：它要等子树停稳，才完成并清理这一次行为。独立使用的原生 StateTree 在退出后可以继续进入其他状态，但再次使用一个仍在清理中的 BT 时，任务会失败。

StateTree 自己不创建、缓存或切换黑板。

## 黑板复用要初始化本次输入

- **黑板归属**：BT 与 HTN 使用的原生黑板归 Controller 管理。
- **复用时保留旧值**：资产布局兼容时会复用已有黑板并保留原来的值。所以“组件被复用”不等于“所有键都已清零”。
- **初始化时机**：原生 Logic 和任务可以覆写 `InitializeBlackboard`，写入本次的目标与参数。它在切换黑板之后、启动树之前调用。只初始化自己负责的键：既不要留下上一次的目标，也不要清掉其他已约定保留的数据。
- **交接失败**：另一个 BT 或 HTN 的使用者正忙时，黑板交接失败，本次启动也随之失败。

## 移动用引擎原生能力

| 后端      | 移动方式                    |
| --------- | --------------------------- |
| Logic     | 直接用 `UAITask_MoveTo`     |
| StateTree | 使用 `FStateTreeMoveToTask` |
| BT        | 使用引擎原生的移动任务      |

取消与完成由当前任务和后端各自的协议处理，StellaAI 不再额外包装移动。路径由项目的 StellaNavigation 提供。

## 退出后新行为迟迟不开始

先在 [AI 调试面板](/read/stellaai-debugging)的 BehaviorTree、StateTree、HTN 面板中确认局部树是否仍在运行或清理。不要用“延迟一会儿再启动下一个行为”去掩盖没有退出的任务。

需要事件图或 latent 节点的自定义动作，使用 [BlueprintBase Logic](/read/stellaai-logic#蓝图-logic)。原生的 BT、StateTree、HTN Logic 不能作为任意蓝图派生的入口。

代码位置（插件 `Source/StellaAI`）：`BehaviorTree`、`StateTree`、`HTN` 目录下的 Logic、任务与组件，以及 `Behavior/StellaAIBlackboard`。
