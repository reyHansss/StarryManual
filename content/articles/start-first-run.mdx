## 运行导航示例

项目目前没有正式关卡，最完整的可玩地图是导航示例 `/Game/Samples/Navigation/L_Navigation`。它的 WorldSettings 指定了示例专用的 Experience `B_NavigationExperience`。

1. 在内容浏览器中打开 `Content/Samples/Navigation/L_Navigation`。
2. 点击工具栏的 Play，开始 PIE。
3. 你会出现在一个白盒场景里，四个角各有一组导航示例：

| 位置 | 示例                   |
| ---- | ---------------------- |
| 左后 | 三层电梯               |
| 右后 | 两个移动平台之间的跳跃 |
| 左前 | 动态障碍               |
| 右前 | 移动并旋转的圆盘       |

示例里的面板靠走进重叠区触发：

- 首层的 `AI TO L1`、`AI TO L2`、`AI TO L3` 命令 AI 前往对应楼层。
- 电梯厅外的面板用来呼梯，轿厢内的面板用来选层。
- 出生点旁的绿色传送门直接通往 L3。

插件 BlockoutTools 另带一张形状总览图 `/BlockoutToolsPlugin/Maps/BlockoutTools_Overview`，用来浏览白盒形状，不包含玩法。

## 打开调试面板

在 PIE 中按 **F1**，切换 StellaDebug 的调试输入：鼠标和键盘交给调试面板，从顶部菜单打开需要的窗口。再按一次 F1 回到游戏操作。**F2**～**F4** 分别载入第 1～3 套窗口布局。

也可以按 `~` 打开控制台，输入 `StellaDebug.ToggleInput`。调试面板只在非 Shipping 构建中可用。各菜单下有哪些工具，见 [StellaDebug](/read/stelladebug-overview)。

## Experience 是怎样选中的

Experience 决定一局游戏装配哪些玩法、使用哪份默认角色数据。GameMode 在开局时按下面的顺序决定使用哪个 Experience，先找到的生效：

1. 地图 URL 参数 `?Experience=`
2. PIE 时的开发者设置：项目设置 → Starry → Starry Developer Settings → **Experience Override**。这是保存在本机的个人设置，不影响其他人。
3. 命令行参数 `-Experience=`
4. 当前地图 WorldSettings 的 **Default Gameplay Experience**
5. 以上都没有时，回退到 `B_StarryDefaultExperience`（位于 `Content/Blueprints/Experiences`）

专用服务器加载默认地图时，第 4 步之后还会尝试走服务器登录与 Playlist 流程。完整的加载过程见[一局游戏怎样启动](/read/arch-startup)。

## 测试地图

各系统的验收场景放在测试目录中，正式内容不引用它们：

| 位置                              | 内容                                                      |
| --------------------------------- | --------------------------------------------------------- |
| `Content/Tests/Ecology`           | 生态测试地图（13 张，含资源生命周期场景）                 |
| `Content/Tests/GAS`               | `L_CombatSample`、`Showcase/L_CombatShowcase` 战斗样例    |
| `Content/Tests/GASP`              | `L_GASP`、`RagdollLevel` 等动画与布娃娃场景               |
| `Content/Tests/StellaAI/Approach` | `L_Approach`                                              |
| 插件 StellaAITests                | `Tests/Encounter/Encounter`、`Tests/Rework/ZoneAuthoring` |
| 插件 StellaNavigationTests        | `Sample/L_StellaNavigation` 等                            |

两个测试插件默认禁用，正式工程不会加载它们。用法见下一节。

## 运行自动化测试

在编辑器中打开 Session Frontend（会话前端）窗口的 Automation 页，按名称筛选后运行。命令行运行时，结果以导出报告里的 `index.json` 为准，不能只看进程退出码：

```powershell
UnrealEditor-Cmd.exe Starry.uproject /Engine/Maps/Entry -unattended -nop4 -nosound -NullRHI -ExecCmds="Automation RunTests Starry.Input" -TestExit="Automation Test Queue Empty" -ReportExportPath=Saved/Automation/Input
```

把 `Starry.Input` 换成要运行的测试名称前缀：

| 前缀                                                                         | 范围                                  |
| ---------------------------------------------------------------------------- | ------------------------------------- |
| `Starry.Ecology`                                                             | 生态（数量最多）                      |
| `Starry.Combat`、`Starry.GAS`、`Starry.GASP`、`Starry.AI`、`Starry.Input` 等 | 项目各系统                            |
| `StellaAI.Rework`                                                            | StellaAI 插件，需要启用 StellaAITests |
| `StellaNavigation`、`StellaPatrol`                                           | 导航与巡逻插件                        |

- **StellaAITests**：编译时加 `-EnablePlugin=StellaAITests`，启动编辑器时加 `-EnablePlugins=StellaAITests`，再运行 `StellaAI.Rework.` 开头的测试。
- **StellaNavigationTests**：不在正式工程里启用。`Scripts/OpenStellaNavigationTest.ps1` 会把插件复制到 `Saved/StellaNavigationSandbox` 的隔离工程，编译后打开测试地图。在当前的目录布局下，运行这个脚本需要显式传入引擎路径，例如 `-EngineRoot <引擎目录>/Engine`，否则它推算出的默认路径不存在。

项目自己的测试源码在 `Source/StarryEditor/Tests` 和 `Source/StarryGame/Tests`。哪些改动需要跑哪些测试，见[日常开发](/read/start-workflow#测试与检查脚本)。
