## 两种修改方式

- **网页编辑器**：在手册仓库运行 `pnpm dev`，打开 `http://127.0.0.1:3210`，点右上角“编辑内容”，或在文章标题下点“编辑本页”。
- **直接改文件**：编辑 `content/articles/` 下的 MDX 文件。

两种方式修改的是同一份内容，都不会自动提交或推送。

首页的“推荐站点”在网页编辑器的“首页推荐站点”中修改，或直接编辑 `content/site-links.json`。

本地静态预览 `http://127.0.0.1:3211/StarryManual/` 读取的是构建产物，修改后要重新构建才会更新；它的编辑入口会跳转到同一台电脑上运行的网页编辑器。

## 文章放在哪个模块

文章按网址前缀自动归入模块：网址是“模块键-名称”，例如 `input-buffer` 属于 Input。模块在 `lib/navigation.ts` 中登记一次（名称、短名、颜色、总览文章），侧栏、模块目录、面包屑、阅读顺序和关系图谱都由它自动生成。

| 模块键        | 模块       | 说明                                                           |
| ------------- | ---------- | -------------------------------------------------------------- |
| `start`       | 入门       | 项目介绍、环境搭建、第一次运行、日常开发、术语表               |
| `arch`        | 架构设计   | 分层、启动流程、对象与数据、协作、网络、来源                   |
| `stellaai` 等 | 各系统模块 | 当前有 StellaAI、StellaDebug、Input、Async Message、AsyncMixin |
| `authoring`   | 手册维护   | 本页与蓝图节点说明                                             |
| `project`     | 项目系统   | 还没有登记模块的文章暂时归在这里                               |

**文章元信息**

| 字段          | 写法                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`       | 模块文章以“模块短名 · ”开头，例如 `Input · 通道输入缓存`；目录与面包屑会自动省略这个前缀                                                                   |
| `description` | 一句话说明这篇讲什么、读完能做什么                                                                                                                         |
| `section`     | 从外到内的功能分区，例如 `[行为执行, 树后端]`；模块总览和快速上手留空                                                                                      |
| `order`       | 同一目录中的顺序。各模块使用自己的号段：入门 1～9、架构 10～19、StellaAI 20～29、StellaDebug 30～39、Input 40～49、Async Message 50～59、AsyncMixin 60～69 |

**站内链接**：写作 `/read/文章网址`，需要定位到小节时加锚点，例如 `/read/input-binding#添加映射时的选项`。正文中的真实链接同时生成关系图谱与“链接到本页”。

## 怎样写

**每个模块的骨架**：模块总览 → 快速上手 → 各功能的机制页 → 调试与排查。小功能合在一页里写完，不为凑结构拆出空页。

**写法规则**：

1. **开头先说用途**：两三句说清这是什么、什么时候用、读完能做什么，再展开细节。
2. **先例子后原则**：步骤要写出预期结果，让读者能判断自己做对了没有。
3. **一段一个意思**：术语第一次出现时给出解释，或链接到[术语表](/read/start-glossary)。
4. **只写已经实现的内容**：类名、默认值、菜单路径按当前源码核对。示例资产和占位名称标明“示例”；尚未实现的内容标明“规划”；按代码推断、没有经过运行验证的结论要写明。
5. **写给读者，而不是写给助手**：读者需要注意的坑放进 `Note` 卡片。不写面向 AI 助手的约束、会话过程，或“本轮没有运行某某”之类的声明。
6. **每篇末尾写“代码位置”**：给出阅读源码的起点。
7. **不引用父项目中面向 AI 的资料**：`check:content` 会拦截这类链接。

## 正文组件

以下组件都已注册到 MDX 与网页编辑器。

### 说明卡片

```mdx
<Note title="资产校验会拦住的配置">

卡片里可以写普通的 Markdown，上下各留一个空行。

</Note>
```

### 图表

填写标题与 Mermaid 文本即可，布局、配色、缩放与全屏由共享组件处理，不写坐标、连线路径或单篇样式。按内容选择图种：

- **关系与流程**：用 `flowchart`；
- **调用先后**：用 `sequenceDiagram`；
- **生命周期**：用 `stateDiagram-v2`；
- **类型关系**：用 `classDiagram`。

时序图加上 `steps` 后，读者可以“逐步播放”，按消息顺序逐条查看：

```mdx
<Diagram
  title="一次请求的往返"
  steps
  source={
    'sequenceDiagram\n  participant A as 调用方\n  participant B as 服务\n  A->>B: 请求\n  B-->>A: 结果'
  }
/>
```

### 蓝图节点

用 `BlueprintViewer` 展示从 UE 复制的节点文本，详见[蓝图节点](/read/blueprint-nodes)。

### 截图

**放图片**：图片放在 `public/images/<模块>/` 下，文件名用英文小写和短横线：

```mdx
<Screenshot src="/images/stellaai/stellaai-aibm-editor.png" title="Behavior Modifier 页签" />
```

`title` 同时用作图注和替代文字，点击图片会在新标签页打开原图，静态发布时自动补上部署路径。

**只截界面本身就是内容的地方**：项目自建的编辑器、关键配置资产、调试面板。能用文字和图表说清的，不截图。

**重新截取**：编辑器截图由 `scripts/ue/capture-editor-screenshots.py` 截取。它在 Starry 编辑器中依次打开指定资产，用引擎的 `EditorShot` 命令截取窗口，不修改或保存任何内容。界面改版后：

1. 运行这个脚本，用法写在脚本开头；
2. 把输出转成 PNG；
3. 替换 `public/images` 下的同名文件。

### 交互演示

演示的计算规则逐条对应项目源码，并有测试锁定。源码规则变化时，同步修改对应的 `lib` 文件与 `tests` 中的用例。

**StellaAI 叠加演示**（`ModifierStackDemo`，规则见 `lib/stellaai-composition.ts`）：

- `层 名称` 开始一层；
- 之后每行一个条目：`AddGroup`／`AddBehavior` 路径 `[Critical|Normal]` 模板名，或 `RemoveGroup`／`RemoveBehavior` 路径；
- 路径用 `/` 分隔组。

```mdx
<ModifierStackDemo
  title="后层覆盖前层"
  source={`层 AIBM_示例_Base
AddGroup Ambient Normal 日常
AddBehavior Ambient/Idle 待机
层 AIBM_示例_Alert
AddGroup Ambient Critical 警戒日常`}
/>
```

**输入缓存演示**（`InputBufferDemo`，规则见 `lib/input-buffer.ts`）：

- **声明**：`模式 LastCommand`；`处理器 名称 缓存 [通道]` 或 `处理器 名称 不缓存`；`动作 名称 处理器…`。
- **事件**：随后按顺序写 `打开 通道`、`输入 动作`、`关闭 通道`、`取消 通道`、`重置`。省略通道时使用 `Input.Buffer.Channel.Default`。

```mdx
<InputBufferDemo
  title="窗口内的两次攻击"
  source={`处理器 Light 缓存
处理器 Heavy 缓存
动作 IA_Light Light
动作 IA_Heavy Heavy
打开 Input.Buffer.Channel.Default
输入 IA_Light
输入 IA_Heavy
关闭 Input.Buffer.Channel.Default`}
/>
```

场景文本有无法识别的行时，演示卡片顶部会列出行号。

## 更新后的检查

**普通内容更新**

- 运行 `pnpm check:content`，核对元信息与站内链接。
- 改名或删除文章时，同步更新链接到它的文章。

**修改了组件或演示规则**

- 运行 `pnpm typecheck`、`pnpm format:check` 和 `node --test tests/*.test.mjs`。
- 打开相关页面，确认显示正常。

**发布构建**

1. `pnpm build:pages --base-path /StarryManual`
2. `pnpm check:pages`

本地保存与构建不会自动发布；推送到 `main` 后，GitHub Actions 才会构建并发布。
