## 打开 AI 面板

在非 Shipping 构建的 PIE 中按 **F1** 切换调试输入，打开顶部的 **AI** 菜单。下面这些窗口共用同一个 AI 调试会话，由 Agents 窗口每帧驱动：

| 窗口               | 看什么                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Agents**         | 列出带 StellaAI 组件的角色并选择其一，选择结果同步到 StellaDebug 顶栏。<br />显示 Controller、Pawn、移动模式，以及寻路、Objective 组件和 Controller 上全部 Brain 的运行状态 |
| **StellaBehavior** | 当前行为集合的树、节点的评估结果、当前执行的详情，下方是 Timeline                                                                                                           |
| **Objectives**     | 当前的机会与生成器                                                                                                                                                          |
| **Modifiers**      | 应用的层与组合结果；可以给选中的 NPC 临时增删 Modifier，并显示被拒绝的原因                                                                                                  |
| **BehaviorTree**   | 节点树（可搜索），活动节点为绿色                                                                                                                                            |
| **StateTree**      | 同上，针对 StateTree                                                                                                                                                        |
| **HTN**            | 节点树、计划实例与每一步的代价                                                                                                                                              |
| **Blackboard**     | 全部键值，包括父资产中的键                                                                                                                                                  |

BehaviorTree、StateTree、HTN、Blackboard 四个窗口不要求角色带 StellaAI 组件，独立使用的原生后端也能看。

面板显示的是 StellaAI 实际发布的评估与执行事件。打开面板不会让组件额外调用条件或评分。

## 读懂 StellaBehavior

**节点颜色**

| 颜色 | 含义                                 |
| ---- | ------------------------------------ |
| 灰色 | 条件未通过、在冷却中，或被优先级屏蔽 |
| 白色 | 最近一次评估可用                     |
| 黄色 | 当前正在执行的行为，以及它的祖先组   |

**节点标签**

| 标签        | 含义                                                         |
| ----------- | ------------------------------------------------------------ |
| `[分数]`    | 最近一次真实评估的分数；条件失败后仍保留上一次的分数         |
| `[CD 秒数]` | 冷却中，显示剩余秒数，优先于分数显示                         |
| `[--]`      | 还没有评估记录；组合一旦变化，评分记录清空，节点回到这个状态 |

**详情区**

- 树上方有搜索框和 **Follow Active**（自动跟随当前执行）。
- 显示当前执行的时长、来源层、执行状态、能否被中断、蓝图类与 C++ 类。
- 可以实时查看 Logic 与 Logic Data 的属性。

## 用 Timeline 回看历史

Timeline 位于 StellaBehavior 窗口下方：

- **控件**：**Record**、**Clear**、**Follow** 和 **Seconds**（显示最近 5～120 秒）。
- **图形**：显示行为执行区间、Objective 泳道、感知事件和察觉曲线，点击图形可以跳到对应的历史记录。横轴为游戏时间（秒）；察觉曲线取各目标累计察觉值的最大值，范围 0～1。
- **历史表**：共六列，可以展开查看当时的 Objective 与 Logic Data 快照；收起图形后仍可查看。
- **采集范围**：只采集当前选中的角色。保留最近 128 条执行、256 条 Objective 寿命、256 个感知事件；察觉值每 0.1 秒采样一次，最多 1200 个。

对象检查器显示的是**当前**对象。要查看几秒前的情况，看 Timeline 里当时采集的快照，不要拿当前的共享模板或当前 Struct 去反推另一次执行的状态。

| 现象                        | 先检查                                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Agents 里没有这个 NPC       | `BrainType` 是否为 Composition；角色是否提供了 AISetup；当前是否是权威端世界                                                         |
| 初始化直接停在 Stopped      | `UStarryAISettings::bDisableLogic` 是否开启；全局禁用时不会开始加载配置                                                              |
| 初始化一直没完成            | 软引用是否能加载；是否收到 `OnAISetupFailed` 及其原因                                                                                |
| AISetup 资产校验失败        | Composition 模式要求 `ModifierStack`、`ObjectiveSetup` 和有效的 `PerceptionSenseProfile`；新建感知配置还要检查感官与 `DominantSense` |
| 新加的 Modifier 没有效果    | 看 Modifiers 面板里它是 Applied 还是 Rejected；检查是否被后层覆盖                                                                    |
| 有机会却不执行              | 机会是否当前有效、精确类型是否匹配；组条件、分数与冷却                                                                               |
| 高分行为没有抢占            | 是否同优先级且严格高分；当前是否在执行 Critical；Pawn 是否带有 `UninterruptibleTags`                                                 |
| 切换配置后一直在等待        | 旧执行的 Cancel／Cleanup 与局部树是否已安全结束                                                                                      |
| 新的执行被旧任务结束        | 异步回调是否保存并校验了原来的执行 Id                                                                                                |
| BT 看起来走完了却按失败结算 | 单次运行是否用 `FinishTree` 明确报告了结果                                                                                           |

记录问题时，同时写下以下信息，方便判断是配置没应用、条件不满足、任务失败，还是回调认错了执行：

- Controller；
- 行为的完整路径；
- 应用句柄；
- 执行 Id；
- 所在的世界；
- 触发的操作。

## 验证一次改动

1. 先验证直接相关的成功与失败。
2. 再检查抢占、配置撤销、角色销毁与复用。
3. 如果修的是接入顺序，先确认原生的初始化与通知是否完整。

一次手动赋值或延迟能绕过问题，不代表找到了原因。
