这一篇把“现在已经做到的”和“计划怎么做的”分开写。规划部分都还没有实施。

## 权威约定

- **按当前世界的 Authority 执行玩法**：单机与服务器是权威端，客户端上的副本不是。项目不另建一套可切换的“权威标志”。
- **服务器不依赖本地玩家**：权威逻辑不依赖 LocalPlayer、界面或本地存档。专用服务器上没有这些对象，功能也必须能运行。
- **本地存档不等于客户端权威**：探索进度走本地存档，但这不意味着客户端拥有战斗结果的决定权。
- **客户端发起的修改要显式走服务器**：调试面板、消息系统都不会把客户端操作自动变成 RPC。

## 已经实现的部分

| 方面             | 现状                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 服务器目标       | `StarryServer` 目标可编译。生态验收中已验证 Server 打包，包内 Dedicated Server 能正常运行（无 LocalPlayer），Mass 与角色在独立进程中联机 |
| 角色移动         | Mover 通过 Network Prediction 复制，角色关闭了引擎的 `ReplicateMovement`。固定 60 Hz 步长，模拟端插值；Chaos 异步物理后端尚未适配        |
| 能力系统         | 玩家 ASC 在 PlayerState，AI 的 ASC 在角色自身，GameState 另有全局 ASC，均为 Mixed 复制模式                                               |
| AI               | 决策与感知只在权威端装配，客户端不运行                                                                                                   |
| 生态             | 结果全部在权威端产生；客户端只读取复制结果：GameState 上的环境与群体计划、角色表现、Mass 的网络副本                                      |
| 任务、阵营、背包 | 任务由 GameState 权威维护并复制；阵营成员与背包使用 FastArray，只有服务器能修改                                                          |
| 复制图           | `UStarryReplicationGraph` 已移植，但**默认禁用**，当前使用引擎的默认复制                                                                 |
| 战斗网络验证     | 同进程的 Listen 与 Dedicated 模式在 75 ms 延迟下通过验证；独立进程只验证了连接                                                           |

尚未验证：Shipping 构建、公网环境、丢包，以及目标规模下的表现。在线平台也还没有接入，配置中没有 OnlineSubsystem 设置。

## 部署规划

以下是推荐的部署方式，**尚未实施**：

| 场景     | 推荐部署                                             |
| -------- | ---------------------------------------------------- |
| 离线单人 | Standalone，本地存档                                 |
| 好友合作 | 由一名玩家充当房主的 Listen Server                   |
| 休闲 PvP | 可以使用 Listen Server，具体规则待定                 |
| 公平竞技 | 专用服务器，部署方式与预算待定                       |
| 公共大厅 | 平台在线服务加独立的社交表现同步，大厅不作为战斗权威 |

这套规划的出发点：

- 当前没有常驻战斗服务器的预算；
- 公共大厅要能看到大量陌生玩家；
- 朋友进入同一环境后，自由探索要保持连续，承接任务时可以有过渡。

## 待决定的问题

- 使用哪个在线平台；
- 合作、大厅等场景的具体人数；
- 共同探索的连续范围，以及访客进度怎样写回；
- PvP 的定位，以及竞技入场数据与结算的信任方案；
- 房主断线时怎样处理（目前不预先实现主机迁移）。

写新功能时，先按[权威约定](#权威约定)判断代码运行在哪一端。规划落地后，这一篇会同步更新。
