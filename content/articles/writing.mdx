## 用网页编辑

在自己的电脑上运行 `pnpm dev`，打开本地手册，点击右上角“编辑内容”，进入文章列表。选择文章后，可以修改标题、简介、主题、阅读顺序和正文。保存后回到阅读页刷新，就能看到更新。

网页编辑器直接写入这份独立仓库里的文章文件。GitHub Pages 发布版提供阅读、搜索与交互；内容在本地修改后重新构建发布。若希望直接在线编辑，仍可通过 GitHub 的文件编辑器修改 MDX；带可视化界面的在线编辑与身份验证需要另行配置。

## 用本地文件编辑

文章放在 `content/articles/`，每篇是一个 `.mdx` 文件。文章开头的标题、简介、主题和阅读顺序会同时用于导航、搜索和图谱。

```md
---
title: 一篇新的说明
description: 用一句话说明这篇文章解决什么问题。
category: guide
order: 20
---

## 从问题开始

写下说明，再链接到相关的页面。
```

正文中的本站链接使用 `/read/文章标识`，例如[架构导览](/read/architecture)。同一份链接关系会出现在图谱和反向链接里，无需再手动维护一张独立关系表。

## 插入交互组件

在网页正文编辑器中，通过组件菜单可以插入“输入缓冲交互实验”“蓝图节点查看器”“自动排版图表”和“说明卡片”。本地编辑时，对应的标签分别是：

```mdx
<InputBufferDemo />

<BlueprintDemo />

<Note title="一条补充说明">

在这里解释使用约束或阅读建议。

</Note>
```

组件在代码中统一维护，文章只负责引用。新增组件需要同步注册到渲染端和网页编辑器；正文不写导入语句和任意脚本。

## 按说明需要选择图表

文章之间的联系适合在知识图谱里探索。正文中的职责协作使用关系图，有分支的步骤使用流程图，调用顺序使用时序图，生命周期使用状态图。先确定读者要理解什么，再选择图种。

在网页编辑器插入“自动排版图表”，填写标题与多行 Mermaid 文本即可。本地文件中使用同一个组件：

```mdx
<Diagram
  title="配置与运行怎样协作"
  source={
    'flowchart LR\n  Config(共享配置) -->|提供规则| Runtime(独立状态)\n  Runtime -->|发送结果| View(表现与反馈)'
  }
/>
```

`\n` 表示换行。节点名、关系和文字决定图表内容，自动布局与手册主题负责排版。日常笔记不用填写坐标、配色、连线路径或动画参数。

可以直接复用[架构导览](/read/architecture)中的关系图、[运行与生命周期](/read/runtime)中的状态图，以及[输入缓冲](/read/input-buffer)中的时序图。先改节点文字和关系，检查一次内容与显示即可；需要观察参数变化时，再引用已有交互组件。

## 避免破坏阅读路径

修改文章的网址标识时，同时更新指向它的链接。删除文章前，先看右侧“链接到本页”。本地命令 `pnpm check:content` 会核对文章元信息与失效链接。

第一次使用时，可以回到[从这里开始](/read/start-here)，再沿着一条完整路线检查更新后的阅读体验。
