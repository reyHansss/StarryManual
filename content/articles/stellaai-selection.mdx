## 每次选择做了什么

`UStellaAIComponent` 在 Tick 中先更新当前的 Logic，然后进行一次选择。Objective 正在更新、组件正在关闭或正在等待旧执行停止时，这一帧不选择。

**评估节奏**

- **Critical 候选**：每次选择都会评估。
- **Normal 候选**：只在评估时机到来时评估。时机指距上次超过 `NormalInterval`（默认 0.2 秒），或有人调用了 `RequestEvaluation()`。
- **自动请求**：每个 Objective 更新批次结束时会自动请求一次评估。`NormalInterval` 是组件上的属性，AISetup 中没有它的配置入口。

**检查顺序的影响**：冷却和优先级屏蔽排在最前面，所以处于冷却或被屏蔽的候选不会运行组条件与评分。

## 谁会胜出

当前**有**正在执行的行为时，先给它重新评分，作为要击败的分数。候选要胜出，必须满足其一：

- 优先级比当前行为高（Critical 高于 Normal）；
- 优先级相同，且分数**严格高于**当前分数。

当前**没有**执行时，第一个通过检查的候选先当选，之后的候选同样要更高优先级或严格更高的分数才能替换它。候选按路径顺序遍历，所以同分时路径排在前面的胜出。

| 情况                            | 结果                                        |
| ------------------------------- | ------------------------------------------- |
| Critical 候选对 Normal 当前行为 | 可以抢占，不受中断许可限制                  |
| 同优先级、候选分数更高          | 当前行为允许中断时抢占                      |
| 同优先级、分数相同              | 不替换                                      |
| 当前正在执行 Critical           | Normal 候选直接跳过，分数再高也不能越级抢占 |
| 当前行为自己的分数不是有限值    | 当前执行被取消                              |

**中断许可**：同优先级的抢占要先询问当前行为的 `CanBeInterrupted`。基础实现读取 **Pawn** 的 GameplayTag，Pawn 带有 `UninterruptibleTags` 中任意一个标签时就不允许被打断。中断许可只拦同优先级的普通抢占，不阻挡 Critical 对 Normal 的抢占，也不阻挡宿主失效或配置撤销引起的取消。

**抢占只做取消**：抢占时组件取消当前执行，等它清理完成后，下一次选择**重新评估全部候选**，不保证一定启动刚才胜出的那个。

## 评分只读，不做事

- **`CanBeActivated`**：判断当前机会是否适合开始。基础实现会检查 `ObjectiveClass`：填写后，要求存在一个当前有效的该精确类型的 Objective。
- **`CalculateScore`**：返回分数，基础实现直接返回 `StaticWeight`（默认 0）。

候选和当前执行都会被反复评分，所以这两个函数只读取当前机会与领域状态。不要在里面领取命令、占用资源或启动任务，否则会被重复执行。

## 激活条件和持续约束要分开写

一个“弹药大于零”的组条件允许射击开始。打出最后一发后组条件不再满足，但这不意味着正在进行的射击要立刻中断，否则一个合法开始的动作会被自己的消耗打断。

- **只在开始时成立**：写在 Group 或 Behavior 的激活条件里，只影响新候选。
- **执行期间必须始终成立**：写在 Logic 的 `IsExecutionValid` 或底层任务自己的有效性检查里。检查失败时，当前执行被取消。
- **条件或配置本身被替换**：属于配置变化，按[组合与覆盖](/read/stellaai-composition#运行时增删-modifier)的规则处理。

## 冷却

| 字段                 | 默认值 | 含义                                         |
| -------------------- | ------ | -------------------------------------------- |
| `CooldownSeconds`    | 0      | 结算成功后，这个路径的行为在多少秒内不可再选 |
| `bCooldownOnFailure` | false  | 开启后，失败也进入同样的冷却                 |

被取消（Aborted）的执行不进入冷却。一旦组件发出取消，这次执行的结果就固定为 Aborted，即使 Logic 随后报告成功也不进冷却。

冷却属于每个 NPC 的运行状态，不要把“上次执行时间”写回共享的 Behavior。业务资源在 Logic 的清理中归还；`OnExecutionFinished` 是清理完成之后的结果通知，不保存状态。

## 为什么没有切换到我想要的行为

按选择顺序逐项核对：

1. 配置是否已经应用：查看 Stack 预览或 Modifiers 面板。
2. 是否在冷却中，或者被正在执行的 Critical 屏蔽。
3. Normal 是否到了评估时机：领域事实变化后可以调用 `RequestEvaluation()`。
4. 祖先组条件、`CanBeActivated`、所需的 Objective 是否满足。
5. 分数是否为有限值，是否严格高于当前行为。
6. 当前行为是否被 `UninterruptibleTags` 阻止打断。
7. 旧执行是否还在等待安全清理。

[调试面板](/read/stellaai-debugging)显示的是实际发生过的评估与执行事件。调试界面本身不会为了显示而重新调用条件或评分。
