## 分层

Starry 从下往上分四层：

- **引擎**：StarryUE，带有项目需要的引擎修改。
- **插件**：引擎插件、项目自维护的 Stella 系列插件，以及少量直接使用的第三方插件。
- **`StarryGame`**：项目主模块，分为可复用的 `Framework` 与具体玩法 `Gameplay`。
- **辅助模块**：`StarrySample` 放示例，`StarryEditor` 放编辑器扩展与测试。

**依赖规则：**

- `Framework` 不 include `Gameplay` 的头文件；
- `StarryGame` 不依赖 `StarrySample` 与 `StarryEditor`；
- 项目插件不依赖 `StarryGame`；
- 正式代码、配置与资产不引用任何测试内容。

这些规则由 `Scripts` 下的检查脚本把关，见[开发约定](/read/start-workflow#测试与检查脚本)。

## 源码模块

| 模块           | 类型    | 进入的编译目标       | 内容                                                 |
| -------------- | ------- | -------------------- | ---------------------------------------------------- |
| `StarryGame`   | Runtime | Editor、Game、Server | 全部框架与玩法代码                                   |
| `StarrySample` | Runtime | Editor、Game、Server | 可运行的示例（目前是导航示例），只依赖引擎与导航插件 |
| `StarryEditor` | Editor  | Editor               | 资产定义与创建菜单、编辑器扩展、项目的编辑器测试     |

## 插件

**项目自维护的插件**统一以 Stella 命名：

- **StellaUtilityAI**：组合决策；
- **StellaNavigation**：导航；
- **StellaPatrol**：巡逻；
- **StellaDebug**：调试工具。

另有两个默认禁用的测试插件 StellaUtilityAITests 与 StellaNavigationTests，正式工程不会加载它们。

**直接使用的第三方插件与代码**保留原名；确需修改时，和引擎修改一样用 `STARRY_SOURCE_MODIFY` 标记：

| 插件或库                                                                                                     | 用途                                        |
| ------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| HierarchicalTaskNetworkPlanning                                                                              | HTN 规划，StellaUtilityAI 的 HTN 后端使用它 |
| Dear ImGui、ImPlot、netImgui                                                                                 | StellaDebug 的界面库与远程显示              |
| CommonGame、CommonUser、CommonLoadingScreen、GameSettings、GameSubtitles、ModularGameplayActors、UIExtension | Epic 提供的通用游戏框架组件                 |
| AsyncMixin                                                                                                   | 按序的异步加载工具                          |
| LanguageOne                                                                                                  | 编辑器的中英界面切换、注释与资产翻译工具    |
| BlockoutToolkit                                                                                              | 白盒形状与原型工具，示例地图用它搭建        |

**主要的引擎插件**：GameplayAbilities、Mover 与 NetworkPrediction、StateTree、Mass 系列、SmartObjects、Enhanced Input、CommonUI、GameFeatures 与 ModularGameplay、PoseSearch 等动画插件、PhysicsControl、GameplayCameras、AsyncMessageSystem。

## 全项目的设计原则

- **领域拥有规则与状态，使用方拥有接入代码**：例如输入只负责把操作交给处理器，移动和技能各自决定能不能执行。
- **配置与运行状态分开**：数据资产描述能力和规则，会被多个角色共享，不保存某个玩家或某个 NPC 的运行状态。
- **谁登记，谁撤销**：订阅、绑定、授予的能力和启动的任务，由发起方在退出时成对撤销。异步回调要核对原来的请求或执行身份，过期的结果直接丢弃。
- **遵循当前世界的 Authority**：
  - 玩法规则在权威端执行；
  - 服务器上的逻辑不依赖 LocalPlayer、界面或本地存档；
  - 客户端发起的修改要显式走服务器，消息和调试工具都不会自动变成 RPC。
- **网络按玩法选择部署**：离线单人用 Standalone；好友合作、休闲 PvP、公平竞技与公共大厅的部署方式已有规划，尚未实施。
- **正式内容不依赖测试**：测试代码、测试资产和测试插件可以整体移除。
- **引擎修改有边界**：只为修复已确认的缺陷，或解决现有公共接口无法解决的问题才修改引擎，所有修改都受 `STARRY_SOURCE_MODIFY` 控制。

代码位置：`Source/StarryGame/Framework`、`Source/StarryGame/Gameplay`、`Source/StarrySample`、`Source/StarryEditor`、`Plugins/`。
