## 同一个 Action 的事件只绑定一次

在同一个 Manager 中，相同的 Input Action 加上相同的触发事件，共用一个输入组件绑定。多份已登记的 Setup 引用它时，Manager 记录各自的使用关系，不会为每个 IMC 再重复绑定。

一个事件可以分派给多个不同的 Handler 对象；同一个 Handler 对象在同一个 Action 的同一事件中只会被调用一次。去重看的是**对象身份**，不是类名：同一个类的两个不同对象会各自处理。

## 添加与移除的规则

| 操作                                        | 结果                                                       |
| ------------------------------------------- | ---------------------------------------------------------- |
| 不同的 Setup 引用同一个 Action 或 Handler   | 按已登记的配置记录使用关系，最后一个使用者移除时才解除绑定 |
| 同一份 Setup 连续添加两次                   | 第二次被拒绝，不会多出一份所有权                           |
| 添加的 Setup 所用的 IMC 已经在 Subsystem 中 | 被拒绝，不论这个 IMC 是哪个系统加进去的                    |
| 移除一份已登记的 Setup                      | 移除这一份配置，不需要和添加次数一一配平                   |
| Setup 的 IMC 里没有任何可以绑定的动作       | 这份 Setup 被直接丢弃                                      |

这套规则有一个直接后果：某个功能的添加因为冲突被拒绝后，它再调用移除，并不等于“撤销我刚才那一次”，而是会移除另一个来源登记的同一份配置。所以每份配置在设计上只能有一个拥有者，进入时添加、退出时移除。

**GameFeature Action `AddInputBinding`**

- **成对增删**：按自己的 `InputSetups` 列表成对添加与移除，不额外记录哪些添加成功了。
- **等待时机**：要等 Hero 组件发出“可以绑定输入”的信号（`BindInputsNow`，或已经处于就绪状态）才会添加。
- **软引用**：列表是软引用，资产没有加载时那一项会被跳过。

出现冲突时，应该整理功能的配置归属，而不是靠计数去掩盖。

## 初始化之前

`AddInputSetupData` 没有成功与否的返回值。

- **排队**：Manager 还没初始化时，配置先进入等待队列，初始化完成后再处理。
- **`HasSetupData`**：只检查已经处理过的配置，不把排队中的当成已经生效。
- **初始化前移除**：在初始化之前调用移除，不会撤销已经排队的配置。

不要用一次 `HasSetupData` 的结果推断异步初始化的最终状态。排查时一起检查 Controller 的输入组件、LocalPlayer、Enhanced Input Subsystem 和 Manager 的初始化顺序。

## 切换角色

| `bResetSetupForNewPawn` | 切换角色时                                                                 |
| ----------------------- | -------------------------------------------------------------------------- |
| `false`（默认）         | 保留 Controller 固定配置与功能配置，只更换旧角色 Provider 提供的那部分配置 |
| `true`                  | 清空后按固定配置重建                                                       |

两种模式都会重新处理新角色提供的配置。运行中不要直接修改一份已经应用的 Setup 资产的 Handler 数组，指望它自动重新绑定；要更新运行状态，就明确地移除旧配置、添加新配置。

## 停用输入与清理缓存

- **`DisableInputProcessing`**：停止项目分派，并清空输入缓存。它不会给所有 Handler 补发 Canceled 事件。
- **移除 Setup**：同样会清空缓存。如果 Action 和 Handler 还被其他已登记的配置使用，绑定保留；最后一个使用者移除后才解除。

技能、移动等业务持有的状态，按各自的生命周期退出，不要等待一条不会到来的“输入取消”通知。

## 添加映射时的选项

Manager 在添加 IMC 时使用 `CreateModifyContextOptions` 生成选项，这个函数可以在派生类中覆写。默认实现为：

| 选项                                | 默认值 | 效果                                       |
| ----------------------------------- | ------ | ------------------------------------------ |
| `bIgnoreAllPressedKeysUntilRelease` | true   | 已经按住的键要先松开再按下，才会触发新映射 |
| `bForceImmediately`                 | false  | 不强制在当帧立即重建映射                   |
| `bNotifyUserSettings`               | true   | 把这个 IMC 登记到玩家输入设置，供改键使用  |

所以新增布尔动作时，已经按住的键通常要松开再按一次。这能防止切换配置的瞬间把旧的按键状态当成新动作，不要误判为绑定失败。

Handler 的共享规则见 [Handler 与能力分派](/read/input-handlers)，缓存命令的清理见[通道输入缓存](/read/input-buffer)，改键登记见[改键与玩家设置](/read/input-settings)。
