1. `Make Async Message Id` 的 `Internal Message Tag` 选择 `Starry.Damage.Message`，输出连接 `Start Listening for Async Message.Message Id`。
2. 从自己的打开、激活或 BeginPlay 执行线启动监听，`Desired Endpoint` 保持为空。高级引脚 `Tick Group` 默认 `Post Update Work`。
3. **`On Message Received`** 接到 `Get Instanced Struct Value` 的执行输入；`Message` 接 `Break Async Message`。
4. `Break Async Message.Payload` 接到 `Get Instanced Struct Value.Instanced Struct`，将 `Value` 的类型确定为 `Starry Verb Message`，例如连接已有的该类型变量或业务处理引脚。
5. 在 `Valid` 分支读取 `Value`；`Not Valid` 表示载荷类型不符。正式角色界面还应检查 `Target` 是自己观察的 Avatar，再处理 `Magnitude` 或更新表现。

普通的 `Then` 输出只表示监听启动后的继续执行，收到消息后执行的是 `On Message Received`。需要监听父标签时，可从 `Break Async Message.Message Source Id` 区分真实来源，再选择正确的载荷类型。

`Message Id` 决定路由，载荷里的 `Verb` 是业务字段，二者不会自动互相填写。`Success` 只表示进入了相关接收队列，不表示接收逻辑已执行。监听要先于发送启动，回调会在监听的接收阶段运行。

这里的手动发送只发布通知，不扣血、不应用 Gameplay Effect，也不自动联网。项目正式伤害路径已经发布消息，不再额外重复发送。已有标签与载荷字段见[项目消息与排查](/read/asyncmessage-project)。

## 保存任务并停止监听

启动监听后，将 `AsyncMessageTask` 输出提升为对象引用变量，例如 `DamageMessageTask`。上图将启动节点的 `then` 接到 Set 保存变量，不接 `On Message Received`；保存任务不需要等第一条消息到达。

关闭界面、结束本次功能或 Actor `EndPlay` 时，按以下顺序清理：

1. 检查保存的任务引用是否有效。
2. 以它为 Target 调用 `Stop Listening for Async Message`。
3. 清空变量；下次启动时创建新任务，避免重复登记。
