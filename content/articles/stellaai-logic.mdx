## Logic 负责“这一次”

Behavior 决定做什么，Logic 负责这一次怎么做：取得目标与资源、启动任务、在结束时全部归还。具体的移动、技能或交互由所属领域实现，StellaAI 不要求交互必须经过 GAS。

每个 Controller 同一时间最多有一个顶层活动的 Logic。旧执行完全清理之后，下一次执行才会开始，不会和旧执行争抢同一批资源。这个限制只针对顶层；BT 或 StateTree 内部照常可以并行组织多个任务。

## 选择状态放在哪里

| 实现方式                                | 状态放在哪里                                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 原生 Logic，没有 UObject 成员状态       | 所有 NPC 共享同一个模板；本次执行的数据存在 `GetInstanceDataType()` 声明的 Struct 中                    |
| 原生 Logic，需要独立的 UObject 成员状态 | 在构造函数中把 `bCreateInstance` 设为 true，实际开始执行时才复制一个实例                                |
| 蓝图 Logic                              | 以 `UStellaAIBehaviorLogic_BlueprintBase` 为父类（菜单项 BehaviorLogic (AIBL)），实际执行时创建独立对象 |

需要蓝图事件图或 latent 节点时，一律从 BlueprintBase 派生。Logic 基类和原生的 BehaviorTree、StateTree、Wait Logic 都不允许蓝图派生。组件不会预先为每个候选复制 Logic，也不会连同所属的 Modifier、Group、Behavior 一起复制。

## 原生生命周期

| 方法               | 什么时候被调用               | 该做什么                                                       |
| ------------------ | ---------------------------- | -------------------------------------------------------------- |
| `Start`            | 被选中时                     | 建立本次任务、订阅与资源，保存需要的执行数据                   |
| `Tick`             | 每帧；取消等待期间也会调用   | 推进当前执行，确认后端是否已经退出                             |
| `IsExecutionValid` | 每帧                         | 检查执行期间必须始终成立的约束；返回 false 时执行被取消        |
| `Cancel`           | 被抢占、配置撤销或约束失效时 | 请求停止自己启动的任务                                         |
| `Cleanup`          | 完成或取消之后               | 解绑、归还资源，并按 `Result` 结算；取消时 `Result` 为 Aborted |

这些方法都由选择器同步调用，传入的 Data 属于当前这次执行。基础 Logic 的默认实现：`Start` 直接报告成功，`Cancel` 直接报告 Aborted。

**取消等待期间**

- `Tick` 仍会被调用，用来确认后端已经退出，但不能借此继续推进正常的动作链。
- 准备提交新动作前，先检查 `Context.Component->CanSubmitActions(Id)`。

**`Cleanup` 的返回值**

| 情况                                                   | 要求                                                               |
| ------------------------------------------------------ | ------------------------------------------------------------------ |
| 普通清理，后端还没安全停止                             | 返回 false，组件稍后再次调用，直到返回 true 才结算与释放           |
| `bForce` 为 true（EndPlay、组件销毁、Controller 拆卸） | 必须立即释放资源。此时返回 false 会被强制再调用一次，并触发 ensure |

**`FinishExecution(Id, Result)`**：只接受当前这一代执行的第一次完成报告；真正的结算等调用栈退出后才进行。

## 异步回调要带着原来的 Id

**启动时**：保存组件的弱引用和本次的 `FStellaAIExecutionId`。

**回调到来时**：

1. 先确认组件还在；
2. 用 `FindLogicData(原 Id)` 取得仍然有效的数据，或者直接 `FinishExecution(原 Id, Result)` 报告结果。

<Note title="两种常见的错误写法">

- **捕获 Struct 地址**：捕获 `FInstancedStruct` 的内存地址跨越异步边界，会在旧执行退出后读到失效内存。
- **读取当前 Id**：在回调里读取组件“当前的”执行 Id 来代替原 Id，会让上一次任务的完成结束掉下一次执行。

</Note>

执行 Id 只回答“是不是同一次 Logic”。资源有自己的生命周期时，回调还要做该领域自己的有效性检查，例如加载句柄、Actor 弱引用。

## 蓝图 Logic

创建 `AIBL_` 蓝图后：

- **`OnStart(Context, Execution)`**：启动动作，完成时调用 `Finish(Result)`。默认的 OnStart 直接报告成功，只建类型而不实现它，是得不到任何行为的。
- **`OnCancel`**：停止自己启动的任务，取消完成后调用 `Finish(Aborted)`。默认实现直接报告 Aborted。取消过程中不能再开始下一段正常动作。
- **`OnCleanup(Context, Execution, Result)`**：同步解除委托、归还资源、处理结果，里面不能依赖 latent 等待。

清理之后，组件清除这个蓝图实例的 latent 动作与定时器，释放引用，交给 GC 回收。

## 写完一个 Logic 后验证什么

1. 先验证正常的成功与失败。
2. 再验证执行中被抢占、配置撤销、宿主结束，以及结束后再次执行。
3. 重点观察以下问题：
   - 有没有重复订阅；
   - 迟到的回调有没有结束掉新的执行；
   - 取消后角色是否还在继续动作；
   - 下一次执行有没有读到上一次的目标。

把动作交给行为树、状态树或 HTN 时的结果与退出规则，见 [BT、StateTree 与 HTN](/read/stellaai-backends)；命令的领取与归还，见[命令](/read/stellaai-commands)。
