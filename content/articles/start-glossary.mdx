按领域分组，每项给出含义和在项目中对应的类型或位置。各名词的详细用法从链接进入。

## 引擎与通用

| 名词                            | 含义                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| PIE                             | Play In Editor，在编辑器里直接运行游戏                                                                                   |
| Authority（权威端）             | 对某个 Actor 拥有最终决定权的一端：单机与服务器上为权威端，客户端上的副本不是。Starry 的玩法规则遵循当前世界的 Authority |
| Listen Server／Dedicated Server | 前者由一名玩家的游戏同时充当服务器；后者是没有本地玩家的专用服务器（项目目标 `StarryServer`）                            |
| GameFeature                     | UE 的功能插件机制；激活时执行一组 GameFeatureAction，向世界添加能力、输入、界面等                                        |
| ModularGameplay／InitState      | 引擎的组件扩展框架。InitState 是组件之间协调初始化的状态链：Spawned → DataAvailable → DataInitialized → GameplayReady    |
| Mass                            | UE 的 ECS 式实体框架，适合大量个体；Starry 的生态用它模拟远处生物                                                        |
| `STARRY_SOURCE_MODIFY`          | StarryUE 中所有项目修改的条件宏，默认开启。见[日常开发](/read/start-workflow#修改引擎或第三方源码)                       |

## 玩法装配

| 名词               | 含义                                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Experience         | 一局游戏的装配清单（`UStarryExperienceDefinition`）：默认角色数据、要启用的 GameFeature、要执行的 Action 与 ActionSet。见[一局游戏怎样启动](/read/arch-startup) |
| ActionSet          | 可被多个 Experience 复用的一组 Action（`UStarryExperienceActionSet`）                                                                                           |
| CharacterData      | 角色的数据配置（`UStarryCharacterData`，对应 Lyra 的 PawnData）：角色类、AbilitySets、默认装备、标签关系、InputSetups、默认相机模式                             |
| CharacterExtension | 角色上的扩展组件（`UStarryCharacterExtensionComponent`，对应 Lyra 的 PawnExtension）：持有 CharacterData，绑定 ASC 并授予、收回能力与默认装备                   |
| Hero               | 玩家角色上的组件（`UStarryHeroComponent`）：在角色数据就绪后接入玩家输入                                                                                        |

## 能力与角色

| 名词       | 含义                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------- |
| GAS        | Gameplay Ability System，UE 的技能框架：能力（GA）、效果（GE）、属性集与表现（Cue）                                          |
| ASC        | AbilitySystemComponent，GAS 的核心组件。玩家的 ASC 在 PlayerState 上，AI 的在角色自身。见[角色与组件](/read/arch-characters) |
| AbilitySet | 一份授予清单（`UStarryAbilitySet`）：属性集、初始标签、GE 和能力，授予后可按句柄整体收回                                     |
| Mover      | UE 的新一代移动组件框架，替代 CharacterMovement；Starry 的角色移动基于它，经 Network Prediction 复制                         |
| GASP       | Game Animation Sample Project，Epic 的动画示例工程；Starry 玩家角色的移动与动画方案以它为基线                                |

## 输入

| 名词          | 含义                                                                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| IA／IMC       | Enhanced Input 的 Input Action（一个动作及其值类型）和 Input Mapping Context（按键到动作的映射）                                               |
| Input Setup   | 把一个 IMC、优先级和若干 Handler 组织成一份可整体增删的输入配置（`UStarryInputSetupDataAsset`）                                                |
| Input Handler | 收到动作事件后执行具体处理（移动、技能、界面）的共享对象（`UStarryInputHandler`）                                                              |
| InputManager  | 只挂在 PlayerController 上的输入管理组件（`UStarryInputManagerComponent`）：应用 Setup、分派事件、带通道缓存。见 [Input](/read/input-overview) |
| 输入缓存      | 在动画窗口内暂存可缓存的输入，窗口结束时再执行。见[通道输入缓存](/read/input-buffer)                                                           |

## AI

| 名词                 | 含义                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- |
| AISetup              | AI 角色的配置资产（`UStarryAISetupDataAsset`）：BrainType、Modifier Stack、Objective 配置、感知配置等               |
| BrainType            | AI 的主决策方式：BehaviorTree、StateTree、Custom 或 Composition（StellaAI 组合决策）                                |
| Brain                | Controller 上负责决策的组件。StellaAI 的主 Brain 是 `UStellaAIComponent`                                            |
| Objective／Generator | Objective 是供决策读取的“当前机会”，Generator 负责生成和维护它们。见 [Objective](/read/stellaai-objectives)         |
| Modifier（AIBM）     | 对行为集合的一层增删配置；Modifier Stack（AIBMS）是有序的 Modifier 列表。见[组合与覆盖](/read/stellaai-composition) |
| Group／Behavior      | Group 筛选候选并决定子项优先级，Behavior 判断能否激活并给机会打分                                                   |
| Logic                | 一次被选中的动作的实际执行者，有 Start／Tick／Cancel／Cleanup 生命周期。见 [Logic](/read/stellaai-logic)            |
| Critical／Normal     | 行为的两级优先级。Critical 每帧评估，可以抢占 Normal                                                                |
| HTN                  | 分层任务网络规划，StellaAI 可以把一次动作交给 HTN 执行                                                              |
| StellaNavigation     | 项目的导航插件：在 UE Recast 网格上适配 Havok AI 的路径、用户边与遍历分析，支持移动平台与 NavLink                   |
| StellaPatrol         | 项目的巡逻插件，提供巡逻区域、连接与选点                                                                            |

## 工具与基础设施

| 名词                 | 含义                                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------------------- |
| StellaDebug          | 项目的 ImGui 调试面板插件（源自 Cog）。见 [StellaDebug](/read/stelladebug-overview)                  |
| netImgui             | 把游戏进程的 ImGui 面板显示到独立桌面程序的远程方案                                                  |
| Async Message System | UE 的异步消息插件，项目用它在系统之间发布解耦的通知。见 [Async Message](/read/asyncmessage-overview) |
| AsyncMixin           | 为宿主排队管理异步加载与有序回调的 C++ 工具。见 [AsyncMixin](/read/asyncmixin-overview)              |
