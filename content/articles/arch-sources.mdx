Starry 的很多部分以成熟方案为起点。把来源讲清楚有两个用处：

- 读源码时知道去哪里对照原版；
- 知道哪些地方被有意改过，不要按原版的文档去用。

## 总表

| 来源                                           | 用在哪里                     | 怎样融合                                                                    |
| ---------------------------------------------- | ---------------------------- | --------------------------------------------------------------------------- |
| Lyra Starter Game                              | Framework 的骨架             | 前缀改为 Starry，按功能迁移；部分系统被替换或删除，见下文                   |
| NinjaGAS 1.12、NinjaInput 6.1、NinjaCombat 5.7 | 能力、输入、战斗             | 完整移植进 Framework，不保留插件副本，和 Starry 已有的设计合为一套          |
| Cog                                            | StellaDebug                  | 改名为 StellaDebug，保留 MIT 许可；删除了网络复制等部分                     |
| FlexPatrol 1.1                                 | StellaPatrol                 | 改名并适配 UE 5.8，替换了项目原有的巡逻实现                                 |
| Havok AI 2020.2                                | StellaNavigation             | 在 UE Recast 网格上移植路径、用户边、遍历分析、切割与避让，不链接 Havok SDK |
| GASP（Game Animation Sample）                  | 玩家角色的移动与动画         | 把示例角色的蓝图逻辑转为 `AStarryPlayerCharacter` 的 C++，沿用 AnimBP 方案  |
| HTN Planning 1.19.2                            | StellaAI 的 HTN 后端         | 保留原插件，只改了 Brain 查询一处上游代码                                   |
| Unreal Fest 2024 的 AI 架构分享                | StellaAI 的设计基线          | 按分享的功能与组件分工实现，分享未公开的细节由项目自行设计                  |
| Dear ImGui 1.92.5、ImPlot、netImgui 1.13.0     | StellaDebug 的界面与远程显示 | 第三方库原样分发，适配代码在插件自己的模块中                                |
| 《怪物猎人：荒野》的生态规则                   | `Gameplay/Ecology`           | 按完整规则复刻，直接放在项目玩法中，不做成 GameFeature                      |

第三方许可与来源记录在项目根目录的 `THIRD_PARTY_NOTICES.md` 和各插件的说明文件中。

## Lyra：被替换的部分

Starry 的 GameMode、Experience、GAS 封装、设置、界面、装备、背包等以 Lyra 为基础，但这几处做了替换：

| Lyra 原版                            | Starry                                            | 原因                                                     |
| ------------------------------------ | ------------------------------------------------- | -------------------------------------------------------- |
| ModularCharacter + CharacterMovement | ModularPawn + Mover                               | 项目移动统一使用 Mover                                   |
| PawnData、PawnExtension              | CharacterData、CharacterExtension                 | 角色数据增加输入配置数组与默认装备，能力随角色授予与收回 |
| LyraInputComponent、InputConfig      | Ninja 风格的 InputManager、Input Setup 与 Handler | 输入改为 Controller 持有，可跨角色复用                   |
| Teams                                | 阵营系统 Factions                                 | 阵营同时覆盖关系、声望与伤害许可                         |
| GameplayMessageRouter                | 引擎的 Async Message System                       | 使用引擎原生的消息系统                                   |

Lyra 的武器、数字飘字、测试，以及它的 GameFeature 插件、地图和美术没有搬入。

## Ninja 系列：融合而不是照搬

三个 Ninja 插件的功能基本完整移植，但不照搬所有继承关系和宿主类型。项目已有的合理设计都保留，重叠的配置和状态合并为一套，包括：

- Mover；
- Experience／GameFeature；
- 来源所有权；
- InputTag 技能槽；
- 阵营；
- AI 的多 Brain 接入。

**几处与原版文档不一致、使用时要注意：**

- **InputManager 只能挂在 PlayerController 上**，不支持挂在 Pawn 上。角色通过 CharacterData 或 Provider 接口提供输入配置。
- **输入核心以 NinjaInput 6.1.1 为基线**：InputManager、Handler 基类、缓存组件按原版恢复；具体的 Handler、Trigger、Modifier 采用项目当前的实现。
- **玩家设置界面统一用 GameSettings**，删除了 NinjaInput 自带的设置与改键 MVVM。
- **删除了 Paper2D 角色**：主网格直接使用角色默认的 `Mesh` 成员。

查阅 Ninja 官方文档时，不能直接套用原版的类名和标签。

## Stella 系列插件

项目自维护的插件统一以 Stella 命名：StellaAI、StellaNavigation、StellaPatrol、StellaDebug。它们曾分别叫 AstraAI、AtlasNavigation、NovaPatrol、HaloDebug，旧名称已全部停用。

| 插件             | 与来源相比的主要变化                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| StellaAI         | 精简重构：Modifier 直接引用共享配置、每个 NPC 只存独立的运行数据；BT、StateTree、HTN 三种后端统一接入 |
| StellaNavigation | 基础网格继续用 UE 原生的 Recast 生成；空间索引使用 UE 的八叉树；壁面导航已归档，不在当前版本中        |
| StellaPatrol     | 直接管理原生 MoveTo 请求；示例与测试放在插件的 Tests 目录，不参与打包                                 |
| StellaDebug      | 删除了网络复制、蓝图 Draw、调试 Possess 等；绘制模块独立为 StellaDebugPaint                           |

## 引擎修改

StarryUE 中的修改都用 `STARRY_SOURCE_MODIFY` 标记，只用于修复已确认的缺陷，或解决现有公共接口无法解决的架构问题。目前的修改包括：

- **AI**：`AAIController` 增加按类型缓存与查询多个 Brain 组件的能力，StellaAI、HTN 与项目代码都依赖它。
- **移动**：为 GASP 迁移需要的 Mover 移动模式补充导出，修正运动学网格的移动警告条件，修复运行时销毁 Mover 基座后的悬空引用。
- **导航**：开放导航异步派发与取消的覆写入口。

修改规范见[日常开发](/read/start-workflow#修改引擎或第三方源码)。

## 曾经尝试、已经回退的方案

- **UAF（Unreal Animation Framework）**：曾尝试迁移，后来全部回退到 AnimBP 方案。相关插件在 `Starry.uproject` 中显式禁用，期间加入的三项引擎补丁也已撤回。
- **壁面导航**：已从 StellaNavigation 的当前版本中归档，普通地面、移动平台、NavLink、遍历等能力保留。
